# Lightweight Deep Research

deep-research 워크플로우의 흐름(분해→수집→검증→종합)을 참고하되, JS 오케스트레이션
없이 **메인 루프 + 서브에이전트 몇 개**만으로 수행하는 경량 리서치 커맨드다.
무거운 IO(검색·fetch·읽기)만 서브에이전트로 격리하고, 얇은 판단(분해·검증·종합)은
메인이 직접 쥔다.

## 입력
`$ARGUMENTS`

먼저 입력에서 플래그를 분리한다: `--verify`(독립 검증 서브 추가)·`save`(reports 저장).
플래그는 하이픈 개수에 관대하게 인식한다 — `--verify`/`-verify`/`verify`, `--save`/`-save`/`save` 모두 같게 처리. 분리하고 남은 나머지를 **조사 질문**으로 본다.

---

## Phase 0 — 구체성 게이트
질문이 막연하면(범위·판단기준·제약 중 비는 게 있으면) **2-3개 명확화 질문을
먼저 던지고 멈춘다**. 서브에이전트는 토큰이 무거우므로 막연한 입력을 흘리지 않는다.
충분히 구체적이면 답을 하나의 정련된 질문으로 엮어 Phase 1로 간다.

## Phase 1 — 질문 분해 (메인이 직접)
정련된 질문을 **3~5개 상호보완 검색 각도**로 쪼갠다. 각도는 도메인에 맞춘다
(예: 기술이면 최신동향·벤치마크·한계·도입사례·비용 / 일반이면 정설·반론·1차자료·실무).
각도끼리 중복이 적게, 각 각도에 구체적 검색 쿼리를 붙인다.

## Phase 2 — 병렬 수집 (서브에이전트, 핵심)
각 각도마다 서브에이전트 1개를, **한 응답에서 모두 동시에** 띄운다
(Agent 도구 subagent_type=general-purpose, 독립 작업이므로 병렬). 각 서브에 지시:
> 담당 각도: "<각도 라벨>" · 쿼리: `<쿼리>`. WebSearch로 상위 결과를 찾고,
> 관련 높은 출처 2~3개를 WebFetch로 읽어라. 원 질문에 답이 되는
> **검증가능한 주장 2~3개**를 추출하되 각 주장에 (a) 출처 URL (b) 원문 직접 인용
> (c) 출처품질(1차/2차/블로그/포럼) (d) 발행시점을 붙여라. 못 찾거나 무관하면
> 빈 목록을 반환하라. 추측·미인용 주장 금지.

서브 결과를 받으면 URL 기준 명백한 중복을 메인이 합친다.

## Phase 3 — 적대적 검증 (메인 직접 / `--verify`면 서브 1개)
모인 주장마다 회의적으로 점검한다: ① 인용이 주장을 실제로 뒷받침하나(과장·오독 아닌가)
② 다른 주장과 모순되나 ③ 출처품질이 주장 강도에 맞나(강한 주장엔 1차자료)
④ 구식인가 ⑤ 마케팅/체리픽 냄새. **불확실하면 폐기 쪽**으로 기운다.
폐기한 주장은 사유와 함께 따로 보관한다(투명성).

`--verify`가 있으면, 살아남은 주장 묶음을 검증 서브에이전트 1개에게 넘겨
"이 주장들을 반박해보라"고 독립 점검시키고 그 반박을 반영한다.

## Phase 4 — 종합 (메인이 직접)
검증된 주장을 raw 나열로 끝내지 말고, 각 발견을 전개한 리포트로 가공한다 — 서브가
돌려준 구조화 결과(주장 한 줄 + 근거 한 줄)를 그대로 베끼면 빈약한 리포트가 되므로
살을 붙인다. 아래는 **최소 뼈대**이며, 구체적 서술 형식·깊이·강조 장치는 **리서치
주제와 성격에 맞게 직접 판단해 정한다** (정량 비교면 표·신뢰도 표기가, 개념·맥락
정리면 산문 전개가 맞는 식 — 양식을 한 틀로 고정하지 않는다).

- **핵심 답** — 원 질문에 정면으로 답한다. 개별 사실 나열 전에 큰 그림(축·구조)을 먼저.
- **확정 발견** — 의미 중복을 병합해 coherent finding으로 묶고, 각 발견을 충분히
  전개한다. 발견별 confidence(상/중/하)와 출처를 밝히고, 수치·강한 주장에는 출처·표본·
  시점 단서를 적절히 붙인다. 주체·시점·제품 혼동 위험이 보이면 짚어준다.
- **폐기·강등된 주장** — 무엇을 왜 버렸는지, 또는 어떤 조건에서만 인용 가능한지 (투명성).
- **남은 의문** — 2~4개.

요청 맥락(경쟁 벤치마킹·내부 보고 등)이 있으면 끝에 시사점을 덧붙인다.
마커·주의 박스·시사점 표기 같은 장치는 도움이 될 때 쓰되 의무는 아니다.

`save`가 있으면 `date "+%Y-%m-%d-%H%M"`로 타임스탬프를 얻어
`reports/REPORT-RESEARCH-<주제슬러그>-<타임스탬프>.md`에 하우스 스타일로 저장한다.
없으면 화면 출력만 한다.
