# blind-reverify — 3회차 블라인드 독립 재검증

작성자가 자기 산출물을 다시 보면 **자기 결론을 확인하는 방향으로 읽는다.** 이 스킬은 그 편향을 구조로 차단한다. 검증자에게 결론을 주지 않고 같은 기준만 준 뒤, 나온 판정이 원본과 갈리는 지점을 공격 목표로 삼는다.

실적: 첫 적용에서 78칸 중 **34칸 불일치**를 드러냈고, 원 보고서에 없던 **결함 8건**을 새로 찾았다. 그중 3건은 원 작성자가 "정정했다"고 믿었던 항목의 **같은 유형 재발**이었다.

---

## ⛔ 실행 거부 조건

다음이면 **만들지 말고 거부한다.** 이유를 말하고 대안을 제시한다.

| 조건 | 이유 |
|---|---|
| **객관 게이트를 설계할 수 없다** | 완료를 셸 exit code로 판정할 수 없으면 회차가 "다 했다"는 자기보고로 조기 탈출한다. 껍데기가 된다 |
| 검증 대상이 아직 없다 | 재검증은 완성된 산출물이 있어야 성립한다. 새 분석이면 그냥 분석을 수행한다 |
| 판정 기준이 문서화돼 있지 않다 | 1회차가 무슨 잣대로 채점할지 알 수 없다. 기준부터 명문화한 뒤 다시 온다 |
| **증거가 재현 불가능하다** | 근거가 회의·인터뷰·기억·미래 예측처럼 다시 확인할 수 없는 것이면 2회차가 반증할 대상이 없다. 기준이 있어도 3회가 껍데기가 된다 |

게이트를 만들 수 있는지 판단하는 기준: **"완료 상태"를 파일 존재·개수·형식·명령 exit code의 조합으로 표현할 수 있는가.**

네 조건을 한 문장으로 줄이면 이것이다 — **R1이 원본을 보지 않고도 같은 잣대로 독자 판정을 낼 수 있는가.** 안 되면 R1은 검증이 아니라 다른 의견을 내는 것이고, R2·R3는 두 의견 중 고르는 일이 되어 **검증이 토론으로 변질된다.**

> ⚠️ **혼합 문서는 거부가 아니라 범위를 자른다.** 대부분의 보고서는 사실층(수치·인용·재현 가능한 근거)과 판단층(방향 제안·전망·설득)이 섞여 있다. 판단층이 있다는 이유로 거부하지 말고, **사실층만 검증 범위로 잘라** 미션에 명시한 뒤 수행한다. 무엇을 범위 밖으로 뒀는지는 마감 보고에 반드시 적는다.

## 절차 (순서 엄수)

### 0단계 — 적격성 확인과 기준 수집

사용자에게 셋을 확정받는다. 모호하면 **한 번에 하나씩** 묻는다.

1. **검증 대상** — 파일 경로
2. **판정 기준** — 원본이 쓴 지표·규칙. 없으면 이 스킬을 쓸 수 없다
3. **완료 조건** — 무엇이 채워지면 끝인가 (게이트로 번역할 재료)

> 대상이 코드베이스를 참조한다면 그 소스가 로컬에 있는지 확인한다. 없으면 clone을 요청하고 멈춘다.

### 1단계 — 객관 게이트 작성

`<작업폴더>/scripts/verify.sh`를 만든다. `templates/verify.sh.tpl`을 뼈대로 쓴다.

검사 항목은 대상에 맞춰 정하되, **아래 다섯은 항상 넣는다.**

| # | 검사 | 통과 조건 |
|---|---|---|
| 1 | 회차 산출 파일 존재 | R1·R2·R3 + 정정 목록 |
| 2 | 판정 칸 채움 | 기준이 정한 칸 수만큼 등급 기입 |
| 3 | **근거 동반** | 칸마다 실행 명령 또는 `파일:줄` 최소 1건. 근거 없는 칸 0개 |
| 4 | 원본 결함 전건 처리 | 확정/정정/반증됨/보류 중 하나로 판정 |
| 5 | 작업물 청결 | 검증이 대상 저장소를 오염시키지 않았음 |

**게이트를 먼저 만든다.** 미션보다 먼저다 — 게이트가 미션의 완료 정의이기 때문이다.

> **검증**: 산출물 0개 상태에서 실행해 **exit 1**이 나오는지 확인한다. 빈 상태에서 통과하면 게이트가 아무것도 검사하지 않는 것이다.

### 2단계 — 미션(PROMPT.md) 작성 후 검토받기

`templates/PROMPT.md.tpl`을 채워 `<작업폴더>/PROMPT.md`를 만든다. 반드시 담을 것:

- **회차 자동 판정** — 산출 파일 존재로 자기 단계를 정한다. 회차마다 다른 프롬프트를 쓰지 않는다
- **판정 기준 전문** — 1회차가 원본을 안 보고도 채점할 수 있어야 한다
- **블라인드 차단 목록** — 원본 보고서, 그 선행 문서, 관련 계획 문서를 **경로로 명시**해 1회차 열람을 금지한다
- **산출 규격** — 게이트가 파싱할 근거 라인 형식
- **금지 사항** — 원본 수정 금지, 대상 저장소 쓰기 금지, **원 분석의 스크립트 재사용 금지**
- **종료 조건** — `verify.sh` exit 0

> ⚠️ **원 분석 도구를 재사용하지 못하게 하라.** 같은 도구를 쓰면 같은 결함을 반복한다. 같은 기준을 **다른 방법으로** 재게 해야 측정 도구의 결함이 드러난다.

작성 후 **사용자에게 보여주고 멈춘다.** 잘못 정의된 미션으로 3회를 돌리면 되돌리기 어렵다.

### 3단계 — 회차 실행

승인되면 서브에이전트를 **순차로** 3회 투입한다. 각 회차에 PROMPT.md 전문을 읽게 한다.

```
R1 (fresh) 원본 미열람, 기준만으로 독자 판정   → R1-blind.md
R2 (fresh) 원본+R1 열람, 반증만 시도            → R2-refutation.md
R3 (fresh) 3자 대조, 최종 판정과 정정 목록      → R3-final.md + CORRECTIONS.md
             ↑ 회차 간 인계는 대화가 아니라 파일로만
```

**반드시 지킬 것**

- `subagent_type: "fork"` **금지** — fork는 부모 대화를 통째로 상속해 블라인드가 무효가 된다
- 호출 프롬프트에 **원본의 결론을 쓰지 않는다.** "PROMPT.md를 읽고 자기 회차를 수행하라"로 충분하다
- 회차 사이에 게이트를 돌려 진행 상태를 확인한다

**회차별 보강 지시** (호출 시 추가)

| 회차 | 보강 |
|---|---|
| R2 | 등급 차이를 **(가) 실질 판정 차이 / (나) 기준 해석 차이**로 분류시킨다. (나)는 정정 대상이 아니라 **기준 정의 보완 대상**이다. 섞이면 정정 목록이 무의미해진다 |
| R3 | R2를 그대로 승인하지 말 것. **직접 실행 근거가 없는 "반증 성공"은 재실행**해 확인시킨다. R2가 제기한 신규 결함도 실재 여부를 재확인시킨다 |

**속도 — R1 병렬 분할**

회차 사이는 순차 의존이라 병렬화할 수 없다. R2는 R1을 읽어야 하고 R3는 둘을 읽어야 한다. 줄일 수 있는 것은 **회차 안**이다. R1의 판정 블록은 서로 독립이므로 fresh 서브에이전트 여럿에 나눠 동시에 돌리고 산출을 이어 붙인다.

```
R1a (fresh) 지표 G1~G3을 전 대상에   → R1-part-a.md ─┐
R1b (fresh) 지표 G4~G6을 전 대상에   → R1-part-b.md ─┴→ cat > R1-blind.md → 게이트
```

> ⚠️ **분할축은 판정 기준(지표·검사 종류)이어야 한다. 대상(항목·번들)으로 쪼개면 안 된다.**
> 같은 지표를 두 에이전트가 나눠 매기면 등급이 갈렸을 때 그것이 실질 차이인지 분할 잡음인지 R2·R3가 가릴 수 없다. 한 에이전트가 한 지표를 전 대상에 매기면 그 지표 안의 일관성은 보장된다.

- **판정 대상이 적으면 나누지 않는다.** 대략 40건 미만이면 분할·병합 고정비가 이득을 넘는다(경험 눈금)
- **블록 배정과 산출 파일명은 호출 프롬프트로 준다.** PROMPT.md는 파일 존재로 회차만 판정하므로, 분할 에이전트가 자기 블록과 `R1-part-*.md` 경로를 호출 시 받지 못하면 저마다 R1 전체를 중복 수행한다
- 분할 에이전트도 **fresh·fork 금지·블라인드 차단 목록 동일**이다
- **병합은 부모가 한다.** 부분 파일을 게이트에 검사시키지 말고, 이어 붙인 뒤 돌린다
- **R2·R3는 분할하지 않는다.** R2는 R1 전체를 봐야 공격이 성립하고, R3는 3자 대조가 임무다

실측 소요는 회차당 15~24분, 3회 53~62분이다(78칸 전수 62분 / 변경분 53분). R1 분할로 R1 구간이 절반가량 줄어든다 — 추정이며 아직 실측하지 않았다.

### 4단계 — 마감

게이트가 exit 0이면 `CORRECTIONS.md`를 읽고 사용자에게 보고한다. 정정 목록은 **세 구획으로 분리**한다.

| 구획 | 내용 |
|---|---|
| **A. 정정 필요** | 사실이 달라 원본을 고쳐야 하는 것 |
| **B. 기준 정의 보완** | 기준이 비어 있어 갈린 것. 등급을 고치기 전에 규칙부터 확정 |
| **C. 신규 결함** | 원본에 없던 것. 심각도 순 |

**원본은 이 스킬이 수정하지 않는다.** 반영 여부와 범위는 사용자가 정한다.

3회 안에 게이트를 통과하지 못하면 **미완 상태 그대로 종료**하고 무엇이 부족한지 보고한다. 통과하지 못한 채 완료를 선언하지 않는다.

## 마감 체크리스트

- [ ] 게이트를 빈 상태에서 돌려 exit 1을 확인했다
- [ ] PROMPT.md를 사용자 검토 후에 실행했다
- [ ] 세 회차 모두 fresh 서브에이전트였다 (fork 아님)
- [ ] 회차 호출 프롬프트에 원본 결론을 넣지 않았다
- [ ] R1을 분할했다면 **병합본**으로 게이트를 돌렸다 (부분 파일 아님)
- [ ] 게이트가 exit 0이다
- [ ] 정정 목록이 A/B/C로 분리됐다
- [ ] 검증 대상 저장소가 청결하다
- [ ] 원본을 수정하지 않았다

## 알아 둘 한계

- **3회차가 모든 것을 잡지는 않는다.** 첫 적용에서 회차들은 등급 기호만 대조하느라 원본의 **합산 산술 오류**를 놓쳤다. 수치가 있는 산출물이면 게이트에 **산술 검산**을 넣는다
- **검증자도 오탐을 낸다.** 첫 적용에서 2회차가 제기한 결함 1건은 3회차가 "측정이 만들어낸 것"으로 기각했다. 그래서 R3에 재확인 의무를 준다
- 서브에이전트는 부모 대화를 상속하지 않지만 **`CLAUDE.md`는 상속한다.** 프로젝트 지침에 검증 대상의 결론이 적혀 있으면 그것이 오염원이 되므로, 그런 경우 `claude -p` headless를 검토한다
