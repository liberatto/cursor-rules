# Confluence 글쓰기 · 수정 (통합)

## 공통 토대 (모든 모드가 딛고 서는 사실 3가지)

1. **`updateConfluencePage`는 본문 전체를 덮어쓴다** — 부분 패치 API가 아니다. 그래서
   "일부만 고치기"는 통째로 덮으면 나머지가 날아가므로 별도 절차가 필요하다.
2. **MCP는 첨부를 업로드하지 못한다** — 실체 첨부 없이 `<div data-type="media">`만
   써넣으면 `UNKNOWN_MEDIA_ID`로 이미지가 사라진다. 파일 반입은 브라우저를 거친다.
3. **CSS·JavaScript는 반입되지 않는다** — 보낸 HTML은 ADF로 변환되므로 `class`·이벤트
   핸들러는 **하드 거부**(본문 미갱신), `<style>`·`<script>`·대부분의 `style` 속성은
   **조용히 소멸**한다. 시각 표현은 네이티브 노드나 이미지 첨부로 만든다
   → [`references/html-nodes.md`] §CSS·JavaScript 반입 한계.

역할 분담: **글 = MCP**(HTML 정밀 제어) · **파일 반입 = 브라우저**(첨부 생성) ·
**부분수정 = read→부분교체→재게시**(보존).

### 모호하면 질문한다 (라우팅 확정 게이트)

요청이 어느 모드인지 갈리는데 잘못 고르면 손실이 큰 경우 — **작업 전 사용자에게
한 가지만 확인**한다. 특히 다음을 구분해야 한다:

- **"컨플에 올려줘"** — 새 페이지를 만들라는 것인가, 지정한 **기존 페이지**에 넣으라는
  것인가? 기존 페이지라면 **그 페이지에 이미 있는 내용을 유지**해야 하나(→ 부분수정),
  아니면 **전면 교체**해도 되나?
- **기존 페이지 대상인데 펼치기·도식·표가 이미 있다** — 전면 작성으로 덮으면 그게
  날아간다. "본문만 고치고 나머지 보존"이면 반드시 **부분수정(safe-edit)** 경로.
- **파일이 포함되나** — 콘텐츠에 로컬 이미지·슬라이드가 들어가면 업로드(Part B)가 필요.

> 판단 기준은 Rule 1과 같다: 오선택 비용이 분 단위면 가장 그럴듯한 모드를 골라 첫 줄에
> 밝히고 진행, **되돌리기 어렵거나(기존 매크로 유실 등) 손실이 크면 한 문항으로 확인**한다.
> 확인엔 `AskUserQuestion`을 쓰면 좋다(예: 대상=새 페이지/기존 페이지, 기존이면
> 전면교체/부분수정).

## 표기 규약 (모드 공통)

- **펼치기 제목 앞에 `📂 `** — 새로 만드는 `<details>`의 `<summary>`는 `📂 [참고] …`처럼
  아이콘으로 시작한다. 기존 라이브 펼치기의 제목은 건드리지 않는다
  → [`references/html-nodes.md`] §펼치기.
- **도식은 SVG 우선** — 같은 도식의 `.svg`·`.png`가 함께 있으면 SVG를 올려 임베드한다
  (PNG는 파생본이라 갱신이 밀리기 쉽다). 기존 페이지 갱신 시에는 **현재 본문이 인용 중인
  형식을 먼저 확인** → [`references/authoring.md`] §파일 형식.

## 검증 (모드 공통 — 스크립트로, 눈으로 세지 말 것)

> ⚠ **번들 스크립트를 건너뛰지 않는다.** 본문 조립은 `scripts/md2confluence.py`가 하고
> (게시 **전** 손실 게이트 = 원고 불릿·`<br>` 개수 대조), 게시 **후** 라이브 대조는
> `verify-parity.py`가 한다 — 둘은 겹치지 않으므로 **둘 다** 돌린다(실측 사고: 자체
> 변환기로 게시하고 `verify-parity.py`를 생략할 뻔함).
> 로컬 .md가 SoT인 작업은 **전면교체도 동기화**이므로 아래 3게이트를 전부 통과시킨다.

| 게이트 | 무엇을 대조 | 방법 |
|---|---|---|
| ① 로컬 ↔ 생성본 | 도식·펼치기 인벤토리, 본문 토큰 | `scripts/verify-parity.py <local.md> <생성 body.html>` |
| ② 생성본 ↔ 라이브 | 노드 카운트·미디어 id·절별 텍스트 길이 | 라이브 ADF 조회 후 구조 지문 대조 → [`references/safe-edit.md`] §게시 후 구조 지문 검증 |
| ③ 렌더링 | 이미지 로드 실패 | 보기 페이지에서 `naturalWidth === 0` 개수 = 0 확인 |

- 게이트 ①의 잔여 diff는 **분류해서 보고**한다. 스크립트 정규화 규칙에서 나오는 정상
  차이는 아래 5종이며, **건수까지 맞춰 보고**한다(실측 예: 27건 = 캡션 7 + `<br>` 14 +
  펼치기 4 + 패널 1 + 링크 1). 분류하지 못한 diff가 남으면 유실이므로 게시를 마감하지 않는다.
  1. **도식 alt 캡션** — `[delete] !도식 N …`. 건수 = 도식 N과 일치해야 한다.
  2. **`<br>` 토큰** — `[replace] 'XXX<br' → 'XXX'`. hardBreak로 변환된 자리.
  3. **`<details>` 내부 제외분** — `[delete] [참고] … 펼치기(Expand) 수록 …`.
  4. **패널 승격분** — `[insert]`로 잡힌다(로컬 헤딩+본문이 생성본에서 패널 한 덩어리가
     되며 토큰화가 어긋남). **방향이 insert면 생성본이 더 가진 것이라 유실이 아니다** —
     반대로 `delete`로 나오면 진짜 유실이니 구분할 것.
  5. **링크 표시텍스트 공백** — `[replace] "(…):" → "(…) :"`.
- 게이트 ②는 라이브 본문을 대화로 끌어오지 않고 **숫자만** 받아 비교한다(본문 재조회는
  토큰을 크게 먹는다). 헤딩·표·행·펼치기·미디어·패널·인용·구분선 카운트가 전부 같고
  절별 텍스트 길이가 일치하면 통과.
- 새 페이지 생성 등 로컬 SoT가 없는 작업은 ①을 건너뛰고 ②③만 수행.
