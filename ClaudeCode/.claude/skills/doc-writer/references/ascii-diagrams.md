# ASCII 도식 골격

배치 주장(소속 · 이동 · 전후)을 그릴 때 쓰는 형태별 골격이다. 발동 조건과 금지선은 [writing-principles.md](writing-principles.md) §8에 있고, 이 문서는 골격과 흔한 실패만 담는다.

**골격을 고르기 전에 확인할 세 줄**(§8.1 요약):

- 한글은 표시 폭이 2칸이고 박스 문자 · 화살표는 폰트에 따라 1칸이나 2칸으로 달라진다. 그래서 **한글 오른쪽으로 열을 맞추면 읽는 환경에 따라 깨진다.**
- 맞춰야 할 세로선 · 테두리 · 주석 열은 **그 왼쪽을 전부 ASCII로** 채운다. 연결선은 `+` `-` `|` `v` 로 긋는다.
- 폭 상한 80칸(한글 2칸으로 계산), 코드펜스 안에 넣고 언어 태그는 붙이지 않는다.

---

## 1. 선형 흐름 — 단계와 입출력

단계가 순서대로 이어지고 각 단계가 무엇을 받아 무엇을 내는지가 중요할 때 쓴다.

```
[1] 타입 식별
      입력: 사용자 요청  ·  출력: PREFIX 확정
    |
    v
[2] 파일명 생성
      입력: PREFIX · 타임스탬프  ·  출력: PLAN-AUTH-2026-08-07-1400.md
    |
    v
[3] 본문 작성
      입력: Persona · 핵심 커버리지  ·  출력: 문서 본문
```

입출력 주석을 **오른쪽 열이 아니라 아래 줄로 내려** 정렬 요구를 없앴다. 단계 이름이 한글이어도 깨지지 않는다.

단계가 6개 이하이고 입출력을 적을 것이 없으면 한 줄 체인으로 줄인다. 아래 줄과 맞출 것이 없으므로 `→` 를 써도 된다.

```
요청 수신 → 타입 식별 → 파일명 생성 → 경로 검증 → 프론트매터 → 본문 작성
```

**흔한 실패**: 각 단계 오른쪽에 설명 열을 세우는 것. 단계 이름의 한글 글자 수가 제각각이라 열이 행마다 다르게 밀린다.

---

## 2. 분기 · 게이트 — 조건과 결과

판정에 따라 경로가 갈릴 때 쓴다. 게이트 · 검사 · 예외 처리가 여기 해당한다.

```
data_checks.py 실행
  |
  +--> PASS: 증표를 기록하고 W3 모델 개발로 진행
  |
  +--> FAIL: 사람이 waiver 에 서명해야 진행
  |          |
  |          +--> 서명함: W3 진행
  |          +--> 미서명: 중단
  |
  +--> 증표 없음: 중단 (exit 2)
```

조건과 결과를 **화살표 뒤 한 덩어리 문구**로 붙여 오른쪽 열을 만들지 않았다. 모든 정렬 지점(`|` 과 `+-->`)이 줄 시작에서 ASCII 로만 떨어져 있다.

**흔한 실패**: `+-- 증표 없음 --> 중단` 처럼 조건을 화살표 왼쪽에 두는 것. 조건에 한글이 섞이면 오른쪽 화살표가 행마다 어긋난다.

---

## 3. 파일 트리 — 소속과 역할

폴더 구조나 소유 경계를 보일 때 쓴다. 항목마다 역할을 한 줄로 붙이는 형태다.

```
lab/
+- aidm/                 AIDM 패키지 본체 (자체 git)
|  +- skills/            스킬 17종
|  +- scripts/           게이트 · 하네스 · 분석 스크립트
|  +- tests/             단위 테스트
+- aidm-extract/         설계 원칙 · 평가 도구
   +- eval/              적합성 검사기 3계층
   +- package/           아키텍처 설계서
```

주석 열 **왼쪽이 전부 ASCII**(경로명과 `+-` 연결선)라 열이 유지된다. 트리는 주석 열이 있는 도식 가운데 유일하게 안전한 형태다.

**흔한 실패**: `├──` `│` 같은 유니코드 트리 문자를 쓰면서 오른쪽에 주석 열을 두는 것. 깊이마다 유니코드 문자 개수가 달라 폰트에 따라 열이 계단처럼 밀린다.

## 4. 레이어 스택 — 계층과 강도

층이 쌓여 있고 위아래 관계 자체가 결론일 때 쓴다.

```
+---------------------------------------------------------
| L3  구조 강제   hook · 스크립트 self-check · 사후 재계산
+---------------------------------------------------------
| L2  상태 파일   게이트 증표 · waiver 서명
+---------------------------------------------------------
| L1  산문 규칙   SKILL.md 지시문
+---------------------------------------------------------
```

**우변을 닫지 않아** 각 층 설명의 길이가 달라도 테두리가 어긋나지 않는다. 층 이름(`구조 강제` · `상태 파일` · `산문 규칙`)은 한글 글자 수가 서로 같아 뒤 열이 함께 밀린다 — §8.1이 허용한 예외 조건이며, 이름 하나만 길이가 달라져도 깨지므로 층이 늘어날 자리에는 쓰지 않는다.

**흔한 실패**: 사방을 닫은 상자로 그리는 것. 오른쪽 세로선을 한글 뒤에 맞춰야 하므로 환경에 따라 어긋난다.

---

## 5. 입출력 관계 — 무엇이 무엇을 만드나

여러 입력이 한 실행 단위로 모이거나, 한 실행이 여러 산출물을 낼 때 쓴다.

```
config.yaml   --+
                +--> run_experiment.py --+--> runs/run-N/metrics.json
recipes/r1.py --+                        +--> _state/experiment-status.yaml
```

여러 줄에 걸친 연결선이 필요한 형태이므로 **라벨을 전부 파일명 · 식별자로** 두었다. 한글 라벨이 필요하면 이 형태 대신 1번(선형 흐름)을 쓴다.

**흔한 실패**: 상자 안에 한글 이름을 넣고 상자끼리 선으로 잇는 것. 선이 만나는 지점이 한글 폭에 의존하므로 어긋난다.

---

## 6. 상태 전이 — 상태와 전이 조건

문서 `status`, 실험 단계, 승인 상태처럼 정해진 값 사이를 오갈 때 쓴다.

```
draft
  +--> (승인) active
  |            +--> (후속 문서가 대체) superseded
  |            +--> (역할 종료) archived
  +--> (기각) rejected
```

중첩된 `+-->` 는 위 줄의 한글 폭에 따라 몇 칸 밀려 보일 수 있으나, 서로는 같은 열에 있으므로 읽힌다. **어긋나도 읽히는 들여쓰기와 어긋나면 깨지는 테두리를 구분하는 자리**가 이곳이다.

**흔한 실패**: 전이 조건을 한글로 적고 그 오른쪽에 세로선을 세워 하위 전이를 매다는 것.

---

## 7. 전후 대비 — 바꾸기 전과 후

구조를 바꾼 결과를 보일 때 쓴다. 좌우 2단이 아니라 **위아래로 쌓는다**.

```
[전] 게이트 강제 = PreToolUse hook 하나
       에이전트 --> Write 도구
                     |
                     +--> hook 있음: 차단
                     +--> hook 없음: 그대로 기록됨

[후] 게이트 강제 = 스크립트 self-check + 사후 재계산
       에이전트 --> run_experiment.py
                     |
                     +--> G2 미통과: exit 2 로 진입 차단
                     +--> hook 있으면 관문이 한 겹 더 붙음
```

전과 후의 **같은 자리에 같은 항목**을 두어야 독자가 델타를 읽는다. 항목 수나 순서가 달라지면 무엇이 바뀐 것인지 보이지 않는다.

**흔한 실패**: 왼쪽에 전, 오른쪽에 후를 두는 2단 배치. 왼쪽 칸의 한글 폭이 오른쪽 칸 전체를 밀어낸다.

## 그리지 않는 자리

| 내용 | 대신 쓸 것 |
| --- | --- |
| 같은 축의 항목 3개 이상 비교 | 표(판정 열 포함) |
| 수량 · 비율 비교 | 표. ASCII 막대는 값 5개 이하이고 규모 차이가 결론일 때만 |
| 개념 정의 · 단일 판정 | 문장(writing-principles §7.10) |
| 노드가 둘뿐인 관계 | 문장. `A → B` 는 도식이 아니다 |
| 본문 문장을 그대로 옮긴 상자 | 삭제. 도식을 지워도 잃는 정보가 없으면 장식이다 |
