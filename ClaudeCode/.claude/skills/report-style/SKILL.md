# report-style — 공식 보고 문체 작성·점검 스킬

> 이 스킬이 **공식 보고 문체(명사형 종결 계열)** 규칙의 단일 SoT. 규칙 본문은 `references/`에 보유(구 `rules/GUIDE-WORKING-DOC-STYLE`를 흡수). 외부 가이드 파일을 참조하지 않음.

## 적용 범위 (2026-08-12 확정)

| 대상 | 이 스킬 발동 |
| --- | --- |
| 공식 보고 3종 = **담당보고·본부보고·부문보고** — 정기 사이클(담당주간·본부/부문 주간·월간)과 그 계위에 올리는 개별 보고 문서 | O (기본) |
| 사용자가 "공식 보고로 올린다"고 **명시**한 기존 문서의 문체 전환 | O |
| "하우스 스타일로"·"문체 점검"·"명사형으로 고쳐줘" 등 문체 작업 **직접 요청** | O |
| 그 밖의 문서 산출물 (GUIDE·NOTE·RESEARCH·ANALYSIS·PLAN·PRD·ADR·HANDOFF·DOCUMENTATION) | X — `doc-writer` 담당 |

- **`doc-writer` 와 배타** — 두 스킬의 어미 규칙은 정반대다(이 스킬 §2.1 명사형 종결 ↔ doc-writer §7.1 평서형 `~다` 종결). 한쪽이 걸린 문서에 다른 쪽을 겹쳐 적용하지 않는다.
- **`scripts/check.sh` 는 이 스킬 대상 문서에만 실행** — `doc-writer` 로 쓴 문서에 돌리면 평서형 종결이 전부 명사형 위반으로 잡히며, 그 수치는 위반이 아니라 규칙 불일치다.
- **전용 스킬 우선** — 담당주간보고는 `weekly-division`, 본부·부문 주간보고는 `weekly-bureau`, 월간보고는 `monthly-report`. 이 스킬은 그 스킬들의 문체 근거와 `check.sh` 를 제공한다.

## 동작 원칙

- **필요한 레이어만 Read** — 전체를 통독하지 말고 작업에 맞는 references 파일만 로드
- **점검은 스크립트로** — 눈 검증 떠넘기지 말 것. `scripts/check.sh`로 위반을 수치로 잡고 "0건"을 보고
- **surgical 교정** — 기존 원고 교정 시 의미·수치·구조 불변, 문체만 손댐

## 1단계 — 작업 유형·레이어 판별

```
모드:   [신규 작성]  또는  [기존 원고 교정]
레이어: [A] 일반 실무 문서  → references/core.md (기본)
        [B] 임원·부문 보고  → core.md + references/executive.md
        [C] 비전문 독자용   → core.md + references/readability.md + references/examples.md (명시 요청 시만)
```

- 판별 근거: 독자(팀 내부 / 상무·본부장·부문장 / 타 팀·외부)와 산출물 종류(PoC 리포트·메모 / 현안보고·전략보고 / 발표·외부 공유)
- 불확실하면 사용자에게 1회 확인. 임원·부문 보고는 거의 항상 [B]
- 발표 도식(SVG)이 포함되면 별도 가이드 `rules/GUIDE-SVG-PRESENTATION-STYLE` 안내

## 2단계 — 해당 레이어 references Read

| 레이어 | Read 대상 |
| --- | --- |
| 공통(항상) | `references/core.md` (자립성·문장·어미·구조·시각·반복패턴·작성 후 체크리스트) |
| 규칙 개정 시에만 | `references/CHANGELOG.md` (규칙이 언제·왜 바뀌었는지 — **작성·교정 작업에는 읽지 않음**) |
| [B] 임원·부문 보고 | + `references/executive.md` (R1~R11·3단 골격과 표 구현형·라벨 구분자 우선순위·볼드 범위·어휘 사전 4군) |
| [C] 비전문 독자 | + `references/readability.md` (가독성 우선 — 섹션 0·용어 풀이) + `references/examples.md` (설명형 예시 8편 — **본문 작성 전 장르 표에서 가장 가까운 2~3편을 읽음**) |

## 3단계 — 작성 또는 교정

**신규 작성**
1. 본문을 core.md 규칙으로 작성 (명사형 종결·자립성·표/ASCII 우선·메타블록)
2. [B]면 R1~R11·3단 골격(Pain Point→개선→기대효과, 방안 3개↑면 AS-IS/TO-BE 4열 표)·정량 볼드 적용. 라벨은 콜론 기본(엠대시 최소), 볼드 경계는 어절에서 끊기, 제목은 행위 서술형
3. [C]면 **본문을 쓰기 전에** `examples.md` 앞부분의 장르 표(소개·비교·원리 설명·판단·권고·경위·원인·숫자 해석·통념 교정·절차 안내)에서 가장 가까운 2~3편을 골라 읽고 그 골격과 어조로 작성 — 예시는 규칙의 보조가 아니라 출발점이며, 베끼는 것은 골격·어조뿐이고 주제·수치는 옮기지 않음. 결론 굳은 뒤 섹션 0(30초 블록) 마지막에 추가

**기존 교정**
1. 원고를 문단 단위로 훑으며 위반 식별
2. executive.md §8.6 Before→After / §8.7 군더더기 사전으로 치환 (의미·수치 불변)
3. surgical 수정 — 위반 문장만 손대고 멀쩡한 곳은 두기

## 4단계 — 기계 점검 (필수)

```bash
bash .claude/skills/report-style/scripts/check.sh <원고.md>          # 공통
bash .claude/skills/report-style/scripts/check.sh <원고.md> --exec   # [B] 엠대시 가드 포함
```

명사형 종결·공손도·한자어·cross-ref·과깊이를 수치로 출력. [B]는 엠대시 빈도(≤1/100줄)·정도부사 단독·볼드 안 어미까지. 위반이 남으면 3단계로 돌아가 교정 후 재점검. **3회 반복해도 남으면 중단하고 5단계에서 항목·사유 보고.** (회피 예시·코드블록 매칭은 오탐일 수 있으니 출력 줄 확인 — 오탐으로 판정한 건은 사유를 적어 5단계에 포함)

## 5단계 — 통과 보고

각 축 위반 건수 + 통과 여부를 표로 보고. 0건이 아니면 어디를 왜 못 고쳤는지 명시(조용히 통과 처리 금지).

## 예외 (스킬 미적용)

짧은 메모·즉답·1단락 답변·세션 임시 산출물은 자연스러운 문체로. core.md §2.6.2의 self-note 예외와 동일.
