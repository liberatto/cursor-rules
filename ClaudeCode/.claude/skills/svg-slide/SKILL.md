# 발표용 SVG 슬라이드 제작

발표 도식이 실패하는 지점은 색·폰트가 아니라 **무엇을 어떤 구조로 보여줄지 정하지 않고 그리기 시작한 것**이다. 이 스킬은 그 순서를 강제한다: **설계 → 확정 → 작성 → 기계 점검**.

## 0. 레이어 판별 (가장 먼저)

작업 시작 전 어느 레이어인지 정한다. 레이어가 폰트 스케일과 구조 골격을 바꾼다.

| 레이어 | 청중 | 참조 파일 | 특징 |
| --- | --- | --- | --- |
| **일반 발표** (기본) | 실무자·세미나·워크숍 | `references/presentation-style.md` | 본문 15~16px, 자유 구조 |
| **임원 보고** | 상무님·본부장님·부문장님 | `references/presentation-style.md` **+** `references/executive-style.md` | 본문 17px·**하한 16px**, **헤더 띠 + 결론 띠** 필수, 도메인 색 고정 |

- 임원 레이어는 일반 규칙을 **덮어쓰는 것이 아니라 얹는다** — 두 파일을 모두 읽고, 충돌하면 executive가 우선.
- **큰 화면·원격(온라인) 상영**이면 일반 발표라도 폰트는 임원 스케일(본문 17, 하한 16)을 쓴다. 멀리서·작은 창으로 보는 조건이 같기 때문이다.
- 여러 장을 연속 제작할 때는 **첫 장에서 정한 레이어·색·폰트를 전 장에 고정**한다. 한 장만 달라지면 섞였을 때 즉시 눈에 띈다.

## 1. 그리기 전 — 설계 4단계와 컨펌 게이트

SVG 코드를 바로 쓰지 않는다. 다 그린 뒤 "담을 내용이 틀렸다"가 드러나면 재작업 비용이 가장 크다. 아래를 **텍스트로 먼저** 정리해 사용자에게 제시한다.

| 단계 | 무엇을 | 핵심 |
| --- | --- | --- |
| ① 메시지 한 줄 | 이 장이 청중에게 남길 **단 하나의 문장** | 한 장 = 한 메시지 |
| ② 정보 인벤토리 | 그 메시지를 받치는 정보 블록을 **빠짐없이** 나열 | **여기서 줄이지 않는다** |
| ③ 구조·관계 | 블록 간 관계(흐름·계층·순환·구성비·비교) 식별 | §2 유형 매핑으로 연결 |
| ④ 레이아웃·시선 동선 | 청중 눈이 따라갈 순서로 배치 (ASCII 스케치면 충분) | 좌→우 / 상→하 / 중심→방사 |

**컨펌 게이트** — 위 4단계를 제시하고 **사용자가 확정한 뒤** SVG를 작성한다.
예외는 둘뿐이다: 사용자가 "설계 생략하고 바로 그려"라고 명시했거나, 확정된 기존 도식의 미세 수정(색·문구·좌표)일 때.

**정보 과밀은 빼기 전에 구조로 푼다** — ①배치 재설계 → ②통합(블록 수 축소) → ③슬라이드 분할 → ④제거(최후). 폰트를 하한 아래로 낮춰 욱여넣는 것은 넷 중 어느 것도 아니고, 가독성만 깎는 회피책이다.

## 2. 도식 유형 — 관계가 유형을 정한다

"무엇을 칠하느냐"가 아니라 "무엇을 그리느냐". 강조할 **관계**를 먼저 정하면 유형이 따라온다.

| 관계 | 유형 |
| --- | --- |
| 순서·흐름·단계 | 박스 + 화살표 |
| 계층·소속 | 트리 |
| 순환·반복 루프 | 원형 배치 + 곡선 화살표 |
| 시스템 레이어 | 가로 띠 중첩 |
| 구성비 (≤5항목) | 도넛·파이 |
| 양·규모 비교 | 막대 / 버블 |
| 집합·교집합 | 벤 다이어그램 |
| 항목 병렬 | 카드 그리드 |
| 2축 평가 | 표 / 2×2 매트릭스 |

**박스형이 기본이다.** 원형·차트는 그 형태가 메시지에 꼭 맞을 때만 — 단순 노드를 원으로 바꾸는 장식적 사용은 의미를 흐린다. 화살표도 방향·인과·순서가 있을 때만 쓴다.

**구체 템플릿은 패턴 라이브러리에서 고른다.** 관계를 정했으면 백지에서 그리기 전에 `references/pattern-library.md`의 **선택 매트릭스(관계·의도 → 패턴)**에서 맞는 패턴을 골라 시작 골격으로 복사한다. 18종 — KPI 스탯 타일 · 도넛 게이지 · 진행 막대 · 아이소타입 / 프로세스 스텝 · 타임라인 · 순환 사이클 · 퍼널 / 계층 트리 · 레이어드 아키텍처 · 네트워크 · 2×2 매트릭스 / Before·After · 막대 차트 · 도넛 구성비 · 벤 / 콜아웃 하이라이트 · 대형 스테이트먼트. 이들은 **컴포넌트(삽입 figure)** — 16:9 캔버스 안에 1~3개를 배치하는 조각이며, 맞는 게 없을 때만 박스형을 직접 구성한다. 18종을 눈으로 훑으려면 `assets/pattern-gallery.html`을 브라우저로 연다.

## 3. 작성 — 골격

`assets/boilerplate.svg`(일반) 또는 `assets/boilerplate-executive.svg`(임원)를 복사해 캔버스·타이틀 골격을 잡고, 도식 본체는 `references/pattern-library.md`에서 고른 패턴 스니펫을 캔버스 좌표에 맞춰 배치·리사이즈하고 더미 텍스트·수치를 실제 값으로 교체해 채운다. 규칙 상세는 references 참조. 절대 어기지 않을 것만 여기 둔다:

- **캔버스 16:9 고정** — `viewBox="0 0 1280 720"`(기본) 또는 `1920 1080`(고밀도, 좌표·폰트 ×1.5). `width`·`height`도 같은 비율
- **첫 요소는 흰 배경 사각형** — 투명 배경은 슬라이드 테마색이 비쳐 글자를 먹는다
- **색은 16진수 하드코딩** — `var(--color-*)` CSS 변수는 발표 도구·뷰어가 해석하지 못해 색이 통째로 빠진다
- **밝은 배경에 흰 글자 금지** — 흰 글자는 어두운 헤더 띠·결론 띠 위에만
- **한글 폰트 스택 필수** — `'Pretendard','Apple SD Gothic Neo','Malgun Gothic',...`
- **타이틀 액센트 바** — 제목 앞 블루 세로 바(6×44~48, rx3), 제목·서브는 바 우측 `x≈70`에 정렬
- **헤더 구분선** — 타이틀 묶음 아래 **풀폭 가로선**으로 헤더와 본문을 가른다. 이 선이 없으면 본문 첫 박스가 헤더 띠처럼 보여 "어디까지가 제목인지" 직관적으로 읽히지 않는다

  ```svg
  <line x1="48" y1="98" x2="1232" y2="98" stroke="#4D73BF" stroke-width="2"/>
  ```

  **색은 타이틀 액센트 바와 같은 `#4D73BF`**. 연회색(`#E1E4EA` 등)으로 깔면 발표 화면·원격 공유에서 사실상 보이지 않아 구분선 구실을 못 한다 — 액센트 바와 한 세트로 읽히도록 같은 농도를 쓴다. 서브타이틀 baseline에서 **12~16px 아래**, 본문 첫 요소는 선에서 **최소 16px 띄운다**
- **자식 박스는 부모 경계와 stroke가 겹치지 않게** — 내부 패딩 16~24px, 좌우 대칭

## 4. 작성 후 — 기계 점검 (필수)

```bash
python3 .claude/skills/svg-slide/scripts/check.py <파일.svg> [--executive]
```

캔버스 비율·CSS 변수·흰 글자·폰트 하한·액센트 바·박스 경계 패딩·여백 균형을 검사한다. **0건 확인 후 마감**한다.

스크립트가 잡지 못하는 것은 눈으로 본다 — 브라우저에서 실제 렌더링을 열어 **한글이 깨지지 않는지, 텍스트가 박스를 넘지 않는지** 확인한다. 스크립트는 좌표를 볼 뿐 글자 폭을 모른다.

`--executive`를 붙이면 폰트 하한이 16px로 올라가고 헤더 띠·결론 띠 존재 여부까지 검사한다.

## 5. 여러 장 연속 제작

세미나·보고처럼 여러 장을 만들 때:

1. **뼈대 장부터** — 전체 논리를 지탱하는 핵심 도식(예: 발전 단계·구조 종합)을 먼저 만든다. 나머지 장이 그 시각 언어를 물려받는다
2. **공통 프레임 고정** — 타이틀 위치·액센트 바·페이지 번호·색 매핑을 첫 장에서 확정해 전 장 재사용
3. **재사용 도식 정비** — 기존 SVG를 가져다 쓸 때는 헤더·폰트를 새 프레임에 맞춰 통일한다. 안 맞추면 섞였을 때 따로 논다
4. **마지막에 일괄 점검** — 전 장에 check.py를 돌리고, 브라우저에서 연속으로 넘겨 보며 톤이 튀는 장을 찾는다

## 이식성 (자족 스킬)

이 스킬 폴더는 **자족적**이다 — 다른 프로젝트·머신에 `svg-slide/` 폴더를 통째로 복사하면 그대로 동작한다. 외부 파일·네트워크·프로젝트 결합 없음.

- **모든 참조는 폴더 내부 상대경로** — `references/`·`assets/`·`scripts/`끼리만 가리킨다
- **`scripts/check.py`는 python3 표준 라이브러리만** 사용(`re`·`sys`·`xml.etree`) — 추가 설치 불필요. 파일 경로를 인자로 받으므로 어디서 실행해도 된다
- **점검 실행 경로는 스킬 위치에 맞춘다** — Claude Code 표준 위치면 `python3 .claude/skills/svg-slide/scripts/check.py <파일.svg> [--executive]`, 다른 곳에 뒀으면 그 경로로 바꾼다
- **폰트만 시스템 의존** — SVG는 Pretendard 우선 스택에 `Malgun Gothic`·`sans-serif` fallback을 두므로 한글 폰트가 없는 환경에서도 깨지지 않고 기본 글꼴로 대체된다
