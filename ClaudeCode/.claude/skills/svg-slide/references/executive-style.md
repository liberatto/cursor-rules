# 임원보고용 SVG 포맷 규칙 (상무급 이상 보고)

> **목적**: 임원(상무·본부장·부문장급) 보고에 삽입할 SVG 도식의 폰트·박스·색·구조 표준. 일반 발표용(`presentation-style.md`)보다 **폰트를 한 단계 키운 임원 특화 스케일**.
> **적용 대상**: 현안보고·전략보고 등 임원 청중 대상 도식 일체
> **최초 작성**: 2026-06-18 13:28
> **상태**: 🟢 확정 규칙
> **자립 문서**: 본 문서만 읽어 임원보고용 SVG 1장을 규칙대로 작성 가능. 외부 참조 불필요

## 0. 핵심 지침 요약 (30초 점검)

| 1 | 철학 | 임원은 **멀리서·짧게** 본다 → 큰 폰트·한 장 한 메시지·결론 우선. 한 장에 「대비·흐름·결론」이 한눈에 |

## 1. 적용 철학 — 왜 임원보고는 다른가

임원 보고는 **30분 안에 의사결정**을 끌어내는 자리이고, 청중은 도식을 **멀리서·짧게** 본다. 그래서 일반 발표용보다:

- **폰트를 한 단계 키운다** — 본문 15~16 → **17**, 하한도 15 → **16**. 뒷자리·대형 스크린에서도 읽힌다
- **한 장 = 한 메시지 + 한 결론** — 도식 하단 **결론 띠**에 그 장의 결론을 한 줄로 못 박는다
- **구조가 곧 논리** — 대비(GAP)·흐름(화살표)·종합(결론)이 **시선 동선만으로** 읽히게 배치
- **색으로 의미를 고정** — 임원은 색을 기억한다. AIDD=블루, 문제=레드처럼 **색↔의미를 일관**시켜 장표가 바뀌어도 같은 색이 같은 뜻

---

## 2. 캔버스·비율

- **16:9 고정** `viewBox="0 0 1280 720"`, `width`·`height` 동일 비율 명기
- 첫 요소로 흰 배경 사각형: `<rect x="0" y="0" width="1280" height="720" fill="#ffffff"/>`
- 고밀도 필요 시 `1920 1080`(좌표·폰트 ×1.5)

---

## 3. 폰트 스케일 (임원보고용 — 1280×720 기준)

> 일반 발표용(`presentation-style.md` §6.2)보다 **전 항목 +2px**.

| 요소 | 크기(px) | weight | 비고 |
| --- | --- | --- | --- |
| **슬라이드 타이틀** | **28** | 700 | 최상단 1줄 |
| 서브타이틀 | **17.5** | 400 | 타이틀 아래 설명 |
| **박스/섹션 헤더** | **18** | 700 | 헤더 띠 안 제목(흰글자) |
| **본문·개조식·불릿** | **17** | 400 / 700 | 일반 텍스트·항목 |
| 결론 띠 메인 | **18** | 700 | 하단 핵심 메시지 |
| 결론 띠 부제 | **17** | 400 | 결론 보조 1~2줄 |
| 부연·연결 라벨 | **16.5** | 400 | 화살표 옆 라벨 등 |
| GAP·강조 기호 | 20 | 700 | `GAP`·핵심 단어 |
| (하한) | **16** | — | **16px 미만 금지** — 미달이면 정보 과밀 신호 |

- **하한 16px** — 임원보고는 칩·부연도 16 이상. 일반 발표용의 12.5~13 부연 라벨은 **임원보고에 쓰지 않는다**
- 16px로 욱여넣어지지 않으면 **폰트를 줄이지 말고** §6 순서(통합·분할)로 구조를 다시 짠다
- weight 2단계: 강조(타이틀·헤더·키워드) 700 / 본문 400

## 4. 색 팔레트 · 도메인 매핑 (고정)

### 4.1 도메인 색 매핑 — 장표 간 일관 (절대 규칙)

> 임원은 색으로 내용을 기억한다. **같은 의미는 늘 같은 색.** 보고 전체에서 아래 매핑을 고정한다.

| 의미 | 계열 | fill | stroke | 헤더 띠(흰글자) | 본문 text |
| --- | --- | --- | --- | --- | --- |
| **AIDD · 개발 · 기본 강조** | 블루 | `#E8F0FE` / `#F7F9FC` | `#4D73BF` | `#4D73BF` | `#1a1a1a` / 강조 `#1a4480` |
| **AIDM · 데이터 분석** | 보라 | `#EEEDFE` / `#F6F5FD` | `#6B5FCB` | `#6B5FCB` | `#1a1a1a` / 강조 `#3D348A` |
| **Skill 자산 · 전환 · 무게중심** | 골드 | `#FBF6E9` | `#B3994D` | `#B3994D` | `#8A6516` / 진 `#5A4A20` |
| **병목 · As-Is · 문제점** | 레드 | `#FDF6F6` / `#FBEEEE` | `#BF6666` | `#BF6666` | `#8A3A3A` |
| **중립 · 보조** | 그레이 | `#F3F4F6` | `#A6ADB8` | — | `#5A6270` / `#333333` |
| **결론 띠 (하단)** | 진남색 | `#3A4A6B` | — | (배경) | 흰글자 `#ffffff` + 하이라이트 `#FBE9B8` |

- **AIDM = 보라 `#6B5FCB`로 통일** (과거 그린 `#408C73` 혼용분은 보라로 수렴). 보고 한 건 안에서 그린·보라 혼용 금지
- 헤더 띠가 진한 색이면 그 위 텍스트는 **흰글자 + 연한 동계열 부연**(예 블루 띠 → `#D6E2F7`, 레드 띠 → `#F6DADA`, 골드 띠 → 흰글자)
- 결론·강조 하이라이트는 **골드 `#FBE9B8`**(어두운 띠 위 노란 강조)

### 4.2 색 규칙
- 모든 색 **16진수 하드코딩**, `var(--*)` CSS 변수 금지
- 라이트·파스텔 배경 → **다크 텍스트**. 밝은 배경에 흰글자 금지
- **흰글자(`#ffffff`)는 어두운 헤더 띠·결론 띠에만** — 스타일 검증 훅의 흰글자 경고는 이 경우 정상(의도된 예외)

## 5. 구조 패턴 (임원보고 불변 골격)

### 5.1 헤더 띠 (섹션 머리)
컨테이너 박스 상단을 진한 도메인 색으로 덮는 **라운드 헤더 띠** + 흰글자 제목. 섹션 번호·제목·우측 보조 라벨.

```svg
<rect x="48" y="96" width="556" height="222" rx="14" fill="#F7F9FC" stroke="#4D73BF" stroke-width="2.2"/>
<path d="M48,112 Q48,96 64,96 L588,96 Q604,96 604,112 L604,140 L48,140 Z" fill="#4D73BF"/>
<text x="70" y="124" font-size="18" font-weight="700" fill="#ffffff">① 섹션 제목 <tspan font-weight="400" fill="#D6E2F7">— 부연</tspan></text>
```
- 헤더 띠 = 상단만 라운드(`path`로 위 모서리만 둥글게), 높이 ~44px
- 우측에 보조 라벨(예 `▶ AIDD 개선 대상`)을 `text-anchor="end"` + 골드 `#FBE9B8`로

### 5.2 결론 띠 (하단 — 임원보고 필수)
도식 **맨 아래 풀폭** 진남색 띠 + 흰글자. 그 장의 **결론 한 줄**을 못 박고, 핵심 단어는 골드 하이라이트.

```svg
<rect x="48" y="572" width="1184" height="120" rx="12" fill="#3A4A6B"/>
<text x="72" y="606" font-size="18" font-weight="700" fill="#ffffff">④ 추진 방향 — … <tspan fill="#FBE9B8">AIDD·AIDM 양 축</tspan>으로 …</text>
```

### 5.3 대비(GAP) 패턴
좌우 박스(갖춤 vs 부재 등) + 중앙 `GAP` + 양방향 화살표. 갖춤=블루·부재=레드로 대비.

### 5.4 흐름 패턴 (하강·전환)
- **하강**: 상단 박스 → 하단 박스로 세로 화살표 + 옆 라벨(여러 줄로 나눠 **중앙 겹침 금지**)
- **As-Is ▶ To-Be**: 상단 레드(현재 문제) → 전환 화살표 → 하단 블루(개선). 같은 보고 안에서 동일 레이아웃 반복

### 5.5 타이틀 액센트 바
모든 도식 최상단 제목 앞 블루 세로 바.
```svg
<rect x="48" y="28" width="6" height="48" rx="3" fill="#4D73BF"/>
<text x="70" y="55" font-size="28" font-weight="700" fill="#1a1a1a">제목</text>
<text x="70" y="84" font-size="17.5" fill="#5A6270">서브타이틀</text>
```

## 6. 레이아웃·여백

- **박스 크게, 캔버스 꽉** — 임원보고 첫 장표는 정보가 알차게 차야 빈약해 보이지 않음. **하단 여백 ≤ 100px**(첫 장표는 ~30px까지 채워도 무방)
- **내부 패딩** — 컨테이너 안 자식 박스는 상하좌우 **16~24px** 띄움, 좌우 대칭. 자식 stroke가 부모 경계와 겹치지 않게(`자식.x+width ≤ 부모.x+width − 패딩`)
- **정보 과밀 시 순서** — ① 배치 재설계 ② 통합(블록 수 축소) ③ 슬라이드 분할 ④ 제거(최후). **16px 미만으로 줄이는 건 금지**
- **한 행에 박스 여러 개** — 폭을 통일하고 우측 패딩 확보(흔한 실수 = 우측 박스만 경계에 들러붙음)

## 7. 작성 후 점검 (체크리스트)

- ☐ **비율** — `viewBox` 16:9, `width`·`height` 동일 비율
- ☐ **폰트 하한** — 본문 **16px 이상**, 타이틀 28·헤더 18·본문 17 위계(§3). 미달이면 재설계
- ☐ **도메인 색 매핑** — AIDD=블루 / AIDM=보라 / Skill·전환=골드 / 병목=레드 / 결론=진남색 일관(§4.1). 보고 전체 동일 색=동일 의미
- ☐ **CSS 변수 0건** — 모든 색 16진수 하드코딩
- ☐ **흰글자** — 어두운 헤더 띠·결론 띠 **위에만**. 라이트 배경 위 흰글자 0건
- ☐ **헤더 띠 + 결론 띠** — 섹션 머리 헤더 띠, 하단 결론 띠 존재(§5.1·5.2)
- ☐ **타이틀 액센트 바** — 제목 앞 블루 세로 바(6×48), 제목·서브 `x≈70` 정렬
- ☐ **박스 경계 패딩** — 자식 박스 stroke가 부모 경계와 겹침 0건, 내부 패딩 16~24px 대칭
- ☐ **여백 균형** — 하단 여백 ≤ 100px, 캔버스 알차게 채움
- ☐ **한글 폰트** — `font-family`에 `Pretendard` 등 한글 폰트 포함
- ☐ **이모지** — 의미 신호로 절제 사용. 복합 이모지(🧑‍💻 등)는 PPT 변환 시 깨질 수 있어 최종 매체에서 렌더 확인
