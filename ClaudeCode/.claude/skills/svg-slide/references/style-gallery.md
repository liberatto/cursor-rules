# 슬라이드 스타일 갤러리 (비주얼 톤 선택)

> **목적**: `pattern-library.md`가 "무엇을 그리나(컴포넌트)"라면, 이 문서는 **"슬라이드 전체를 어떤 톤으로 입히나(비주얼 아이덴티티)"**를 고르는 레이어. 둘은 **직교하는 두 축** — **스타일을 먼저 고르고(6종), 그 안을 컴포넌트로 채운다(18종)**.
> **시각 인덱스**: 6종을 한 장에 비교하려면 `../assets/style-gallery.svg`를 브라우저로 연다(1920×1080, 각 프레임 = 독립 슬라이드 축소본).
> **기존 레이어와의 관계**: `SKILL.md §0`의 일반/임원 레이어는 **폰트·격식 규모**를 정하고, 이 스타일 축은 **비주얼 톤**을 정한다. 예: 임원 레이어 + Executive Grid 스타일 / 일반 레이어 + Dark Tech 스타일.

## 2. 사용 절차 (2축 결합)

1. **레이어 판별**(`SKILL.md §0`) — 일반/임원, 폰트 규모 결정.
2. **스타일 선택**(이 문서) — 청중·목적으로 6종 중 하나. 여러 장이면 **첫 장에서 정한 스타일을 전 장에 고정**(SKILL.md §5).
3. **설계 4단계**(`SKILL.md §1`) — 메시지·정보·관계 확정 후 사용자 컨펌.
4. **컴포넌트 채움**(`pattern-library.md`) — 관계에 맞는 도식을 골라 그 스타일의 색·톤으로 배치. 스니펫의 파스텔 색을 **선택한 스타일 팔레트로 교체**한다.
5. **캔버스 확장** — 스타일 갤러리의 각 프레임은 560×315 축소본이므로, 실제 슬라이드는 **1280×720**(또는 1920×1080)으로 좌표를 펼친다.
6. **점검** — `check.py`로 마감. 볼드 4종은 `--bold`(§3).

## 3. 볼드 트랙 & check.py 완화 규칙

볼드 스타일(다크·그라디언트 배경)은 하우스 기본 점검의 일부 축과 **정당하게 충돌**한다. `--bold` 플래그가 그 축만 완화한다.

```bash
python3 .claude/skills/svg-slide/scripts/check.py <파일.svg> --bold
```

| 축 | 일반 | `--bold` | 이유 |
| --- | --- | --- | --- |
| 흰 배경 rect | 필수 | **완화** | 다크/그라디언트 배경이 의도 |
| 흰 글자 | 밝은 배경 위 금지 | **완화** | 다크 배경 위 흰 글자가 기본 |
| 타이틀 액센트 바 | 필수 | **완화** | 스타일별 고유 헤더 사용 |
| 헤더 구분선 | 필수 | **완화** | 다크 슬라이드는 구분선 불필요 |
| **16:9 · CSS변수 · 한글폰트 · 폰트 하한 · 박스 겹침 · 여백** | 적용 | **그대로 적용** | 볼드여도 지켜야 할 불변 |

- **폰트 하한은 볼드에서도 유지** — 다크 슬라이드라고 15px 미만을 허용하지 않는다. 갤러리 축소본의 9.5~14px는 **썸네일이라서**이며, 실제 슬라이드로 펼치면 15px 이상으로 커진다.
- **라이트 2종(01·05)은 `--bold` 불필요** — 하우스 규칙 그대로 통과한다.

> ⚠ **check.py의 transform 한계** — 이 스크립트는 좌표만 읽고 `transform="translate()"`를 해석하지 않는다. 스타일 갤러리처럼 `<g transform>`으로 프레임을 배치한 SVG는 **여백·박스 겹침 판정이 부정확**하다. 단일 슬라이드(중첩 transform 적은)에서는 정확하므로, 실제 산출 슬라이드에 돌릴 때는 신뢰할 수 있다. transform이 많은 레이아웃은 그 두 축을 눈으로 재확인한다.

## 4. 스타일 ↔ 컴포넌트 매칭 가이드

각 스타일이 특히 잘 받는 컴포넌트(`pattern-library.md`):

- **Executive Grid** ← KPI 스탯 타일 · 프로세스 스텝 · 콜아웃 하이라이트 (결론띠와 궁합)
- **Dark Tech** ← 네트워크·연결 · 레이어드 아키텍처 · 도넛 게이지 (네온 강조)
- **Editorial** ← 대형 스테이트먼트 · Before/After (한 방 메시지)
- **Data Story** ← 막대 차트 · 진행 막대 · 도넛 구성비 (숫자 중심)
- **Modular Cards** ← 카드 그리드형 전반 · 아이소타입 · 콜아웃
- **Blueprint** ← 레이어드 아키텍처 · 네트워크 · 프로세스 스텝 (시스템 맵)
