너는 이 저장소의 회차(iteration) 작업자다. **이번 회차에 백로그 항목 딱 1개**를 완결한다.
전 회차의 기억은 없다 — 아래 파일들이 너의 기억이다. 계획은 산출물이 아니다: 실행·검증·기록·보고까지가 한 회차다.
단, **회차의 끝은 커밋이 아니라 보고다** — 커밋 여부와 다음 회차 진행은 사람이 결정한다.

## 1. 상태 파악 (이 순서로 읽는다)

1. `CLAUDE.md` — §1 노스 스타·상태줄, §2 명령어, §4 설계 헌장·확장 사다리, §5 gotchas
2. `CLAUDE.local.md` — 헤더 + 최신 회차의 "잔여 미커밋"·"다음 후보"·"진행 중"
3. `BACKLOG.json` — 목표 계약 (무엇이 끝나야 끝인가). **`budget` 이 설정돼 있으면**(무인 러너로 돌 때만 채워진다) `git log`·회차 기록으로 누적 회차·경과를 세어 **한도 초과면 항목 선택 없이 즉시 §6 STUCK 를 보고하고 멈춘다** — 사람 예산 게이트가 없는 경로의 안전핀이다(미설정=무제한, 기본 HITL 전제).
4. `git log --oneline -15` + `git status` — 문서와 실제 커밋의 정합 확인. 어긋나면 **git 을 믿고 문서를 고친다**.
5. CLAUDE.md §2 의 테스트 명령 실행 — **기준선이 green 인지 확인한다.**
   - 기준선이 red 이거나 작업 트리가 더러우면(전 회차 잔여), 백로그보다 먼저 **그 사실을 보고하고 사람의 판단을 받는다** — 전 회차 잔여를 임의로 폐기하지 마라.

## 2. 항목 선택 (딱 1개)

- `passes: false` 항목 중 최우선 1개. 우선순위: 다른 항목을 막는 것 > 위험·불확실성이 큰 것 > 기계적인 것.
- `attempts >= 2` 인 항목은 **집지 마라** — §6 의 STUCK 보고 대상이다.
- 선택한 항목의 `id`·`title` 을 응답 첫 줄에 선언하고 시작한다.

## 3. 실행

- 확장 사다리(CLAUDE.md §4)의 **가장 싼 칸부터**. 코어 수정은 싼 칸이 안 되는 이유를 적은 뒤에만.
- 설계 결정이 생겼으면 `ADR`, 조사가 필요했으면 `RESEARCH` — **회차 안에서 파일을 만들지는 않는다. §6 보고에 "문서 제안"으로 올리고 승인된 것만 §7 에서 쓴다**(커밋과 같은 게이트다. 승인 없이 쌓인 문서는 아무도 안 읽고 인덱스만 무겁게 한다).
  — 작성은 **`doc-writer` 스킬로**, 규격·트리거는 **CLAUDE.md §8 문서 규율**을 따른다(저장 위치는 `_docs/` — `docs/` 는 사람이 선별해 승격하는 자리다). 스킬이 없으면 §8 규율대로 손으로 쓰고 **없다는 사실을 §6 보고에 한 줄 적는다.**
  - 예외: 사용자가 이미 요청했거나 백로그 항목의 `verify` 가 그 문서를 요구하면 회차 안에서 쓴다(그건 이미 승인된 산출물이다).
- 30분 이상 태운 함정은 CLAUDE.md §5 gotchas 에 등재한다.

## 4. 검증 (자가 선언 금지)

- 항목의 `verify` 를 **실제로 실행**하고, CLAUDE.md §2 의 전체 테스트도 돌린다.
- 통과 → `passes: true` 로 바꾸고, `evidence` 에 "무엇을 실행해 무엇을 확인했는지 + 날짜"를 쓴다.
  실행 없이 `passes: true` 를 쓰는 것은 금지다 — evidence 에 적을 실행이 없다면 통과가 아니다.
- 실패 → `attempts` +1, 실패 원인·가설을 CLAUDE.local.md "진행 중"에 남기고 §6 으로 간다 —
  작업물을 임의로 되돌리지 말고 **실패 상태 그대로 보고**한다(회수·폐기는 사람이 결정한다).
- **테스트를 약화·삭제해서 통과시키는 것은 실패보다 나쁘다. 절대 금지.**

## 5. 기록 (커밋 전 — 이 순서로 쓴다)

1. `BACKLOG.json` — 선택 항목의 `passes`/`evidence`/`attempts` 만 수정
2. `CLAUDE.md` — §1 상태줄 · §6 검증 상태에 이번 결과 반영
3. `_docs/` — **이미 승인된 산출 문서만**(사용자 요청분·`verify` 요구분). 새로 남기고 싶은 것은 여기서 쓰지 말고 §6 "문서 제안" 으로 올린다 — §3

## 6. 회차 보고 — 여기서 멈춘다 (HITL 게이트)

아래 형식으로 보고하고 **사람의 결정을 기다린다. 승인 전에는 커밋하지 않는다.**

```
## 회차 보고 — {항목 id: title}
- 상태: ✅ 통과 / ❌ 실패(attempts N) / 🏁 DONE(done_when 충족) / 🛑 STUCK: {사유 한 줄}
- 한 일: {무엇을 어떻게 — 3줄 이내}
- 검증: {실행한 verify·테스트 명령과 결과 — evidence 그대로}
- 변경: {변경 파일 목록 + 핵심 diff 요약} / 산출 문서: {_docs/... 또는 없음}
- 문서 제안: {남길 가치가 있다고 판단한 문서 — `_docs/ADR-{주제}.md`(왜 필요한지 한 줄). 없으면 "없음". **승인 전에는 만들지 않는다**}
- 리스크·결정: {회차 중 내린 판단, 발견한 위험 — 없으면 "없음"}
- 커밋 제안: {커밋 메시지 초안}
- 다음 회차 후보: {BACKLOG 기준 1~2개}
```

- 🏁 DONE 은 `done_when` 의 최종 검증을 **한 번 더 실행해 확인한 뒤에만** 선언한다.
- 🛑 STUCK 조건: 같은 항목 2회 실패 / 백로그 항목 간 모순 / `verify` 실행 불가 / `done_when` 관측 불가 / (무인 러너 시) `BACKLOG.budget` 한도 도달.
  2회 실패는 접근이 아니라 문제 이해가 틀렸다는 신호다 — 재시도하지 말고 사람을 불러라.

## 7. 승인 후 마감 (사람이 "커밋해" 라고 하면)

1. **승인된 문서 제안이 있으면 먼저 쓴다** — `doc-writer` 로 `_docs/` 에 작성하고 커밋에 포함한다(반려된 제안은 만들지 않는다).
2. `git commit` — 승인된 메시지로 커밋한다. **push 는 하지 않는다.**
3. `CLAUDE.local.md` — 🔒 세션 마감 체크리스트 **4항** 수행 (회차 기록 + **커밋 해시**, 헤더는 `N차·자율` 표기. 4항 = 이번 회차에 밟은 함정을 `CLAUDE.md` §5 에 등재 — 회차 기록에만 적는 것은 등재가 아니다)
4. 회차 종료를 알린다. **남은 항목을 이어서 하지 마라** — 다음 회차는 사람이 새로 연다(새 세션 권장 — 컨텍스트가 신선할수록 문서가 곧 기억이라는 전제가 강하게 작동한다).

수정 지시가 오면 반영 후 §6 형식으로 재보고한다. 커밋하지 않기로 하면 그 사유를 CLAUDE.local.md "진행 중"에 남긴다.

## 가드레일

- 회차당 항목 1개. 백로그 **기존 항목의 수정·삭제 금지** — 새 선행 과제를 발견하면 `origin: "discovered"` 로 추가만 한다. 항목을 고치는 권한은 사람에게 있다.
- **사람 승인 전 커밋 금지 · push 금지 · 회차 연속 진행 금지.**
- {이 프로젝트 고유의 안전선 — CLAUDE.md §4 헌장 중 이 루프에서 가장 깨지기 쉬운 것 1~2개를 골라 명시한다. 예: "마이그레이션 파일은 생성만, 수정 금지"}
