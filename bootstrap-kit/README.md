# 프로젝트 부트스트랩 키트 — Claude Code 작업 패턴 이식용

**기본 3파일 복사로 셋업이 끝난다. 자율 루프(§10)까지 원하면 +2파일.**

| 파일 | 복사 후 이름 | 역할 |
|---|---|---|
| `CLAUDE.template.md` | `<새프로젝트>/CLAUDE.md` | **정본** — 불변의 것(목표·구조·원칙·함정) |
| `CLAUDE.local.template.md` | `<새프로젝트>/CLAUDE.local.md` | **시간축** — 회차 기록·다음 후보 |
| `README.md` (이 파일) | `<새프로젝트>/_docs/bootstrap-kit/README.md` | **규칙서 겸 상기용** — 왜 이렇게 만들었는가 |
| `BACKLOG.template.json` (선택) | `<새프로젝트>/BACKLOG.json` | **목표 계약** — 자율 루프 모드 전용 (§10) |
| `PROMPT.template.md` (선택) | `<새프로젝트>/PROMPT.md` | **회차 헌법** — 자율 루프 모드 전용 (§10) |

> **폴더째 복사를 권장한다.** 이 README 는 셋업 1회용이 아니라, **몇 달 뒤 "이 파일들이 왜 이 모양이더라?" 를 상기시키는 근거 문서**다. 신규 프로젝트의 `CLAUDE.md` §8 에서 이 경로를 가리키게 해두면(템플릿에 이미 들어있다) Claude 도 사람도 규칙의 출처를 되짚을 수 있다.

> **출처**: 이 패턴은 발명이 아니라 **추출**이다 — 실제 프로젝트를 6주(20회차) 개발하며 굴러간 실물을 일반화했다. 특히 §4 의 세션 마감 루프는 **실제로 20차 기록이 통째로 누락되는 사고를 겪고 나서** 생긴 방어 장치다.

## 0. 🤖 Claude Code 에게: 셋업을 요청받았다면 이대로 하라

> 사용자가 **"이 README 읽고 셋업해줘"** 라고 하면, 아래를 **순서대로** 실행한다. 이 절은 사람이 아니라 **너에게 하는 지시**다.

**Step 1 — 이 키트의 위치를 먼저 확정한다.** 절대경로를 가정하지 마라. 이 README 가 있는 폴더가 곧 `KIT` 이다.

```bash
# 이 README 의 실제 위치를 찾는다 (저장소 어디에 복사됐든)
find . -name 'CLAUDE.template.md' -not -path '*/node_modules/*' | head -1
```

**Step 2 — 템플릿 2개를 저장소 루트로 복사(이름 변경)하고, gitignore 를 건다.**

```bash
cp -n "<KIT>/CLAUDE.template.md"       ./CLAUDE.md        # -n: 기존 파일 덮어쓰기 방지 — 이미 있어서 복사가 안 됐으면 사용자에게 물어라
cp -n "<KIT>/CLAUDE.local.template.md" ./CLAUDE.local.md
# ② 시간축은 로컬 전용 (§4) — 중복 등록 방지
grep -qxF 'CLAUDE.local.md' .gitignore 2>/dev/null || printf '%s\n' 'CLAUDE.local.md' >> .gitignore

mkdir -p ./_docs     # 산출 문서의 기본 자리 (§3 "문서 저장 위치")
```

> ⚠️ **gitignore 하는 것은 `CLAUDE.local.md` **뿐**이다.** `_docs/` 는 **git 으로 추적한다** — 계획·조사·설계 결정이 담기므로 팀과 공유되고 이력이 남아야 한다. "언더스코어로 시작하니 임시 폴더겠지" 라고 넘겨짚어 `.gitignore` 에 넣지 마라.

**Step 3 — 저장소를 실제로 탐색한다.** 추측으로 템플릿을 채우지 마라. 최소한 이것들을 **읽고** 사실을 확보한다:
- 패키지 매니저·가상환경 규약(`pyproject.toml`/`package.json`/`uv.lock`/`.venv` 등) → §2
- 진입점·주요 디렉토리의 **경계와 계약** → §3 (`ls` 트리를 옮겨적는 게 아니다)
- 테스트 명령을 **실제로 실행**해서 통과 수를 확인 → §1 상태줄·§6 (**실행 없이 숫자를 쓰지 마라**)

**Step 4 — 채울 수 없는 것은 물어라.** 특히 **§1 노스 스타는 코드에서 유추할 수 없다.** 사용자에게 직접 묻는다:
1. 이 프로젝트가 **끝내 무엇이 되면** 성공인가? (한 문장, 관측 가능한 상태로)
2. 지금 가로막고 있는 **다음 벽**은 무엇인가?
3. 어떤 기능을 추가하든 **절대 훼손하면 안 되는 것**은? (→ §4 설계 헌장의 씨앗)

**Step 5 — 안 쓸 섹션은 지운다.** 신규 프로젝트 1일차엔 **§1·§2·§8 만 남기고 §4~§7 은 통째로 삭제**해도 된다. 내용 없는 헤딩은 매 세션 토큰만 먹고 판단을 돕지 않는다. 섹션은 **쓸 게 생겼을 때 자란다.**

**Step 6 — §9 의 추천 스킬을 확인하고, 없으면 알린다.** 문서 산출물이 나올 프로젝트라면 **`doc-writer` 는 사실상 필수**다 — 채워 넣은 `CLAUDE.md` §8 문서 규율이 **문서 작성을 이 스킬로 보내기 때문이다**(Claude 가 스스로 제안해 승인받은 ADR·RESEARCH 포함). **이 스킬은 키트에 동봉돼 있지 않다** — `~/.claude/skills/doc-writer` 와 `./.claude/skills/doc-writer` 를 확인해 **둘 다 없으면 "없다 · 원본 경로를 알려달라" 를 Step 9 보고에 반드시 넣는다.** 추측해서 만들지 말고, 조용히 넘어가지도 마라 — 안 알리면 문서 규율이 첫날부터 안 걸린다.

**Step 7 — (선택) 자율 회차 모드를 물어보고, 원하면 2파일을 추가한다.** 사용자에게 "회차 단위로 Claude 에게 통째로 맡기고, 회차마다 보고받고 커밋을 승인하는 방식(HITL, §10)으로 운영할 계획인지" 묻는다. 원하면:

```bash
cp -n "<KIT>/BACKLOG.template.json" ./BACKLOG.json   # 목표 계약 (git 추적)
cp -n "<KIT>/PROMPT.template.md"    ./PROMPT.md      # 회차 헌법 (git 추적)
```

백로그 항목은 **Step 4 의 노스 스타 답변에서 도출**하되, `verify` 를 쓸 수 없는 항목은 넣지 마라 — 쪼개거나 사용자와 판정 기준을 합의한다(§10). 원하지 않으면 건너뛴다 — 나중에 §10 만 보고 추가할 수 있다.

**Step 8 — 템플릿 안내 주석(`<!-- ... -->`)을 전부 제거한다.** 채운 뒤엔 안내문이 남아 있으면 안 된다.

**Step 9 — 보고한다**: 무엇을 채웠고, 무엇을 **실행해서 확인**했고, **스킬은 어떤 상태인지(설치함 / 이미 있음 / 없어서 원본 경로 요청)**, 무엇을 사용자 답변 대기로 비워뒀는지.

> ⚠️ **하지 말 것**: 템플릿의 `{중괄호}` 자리를 그럴듯한 추측으로 메우는 것. 이 파일은 **매 세션 로딩되는 정본**이라, 여기 박힌 거짓말은 프로젝트 내내 Claude 를 오도한다. **모르면 비워두고 묻는다.**

## 1. 핵심 아이디어 — Claude 의 기억을 3층으로 쪼갠다

Claude Code 는 **매 세션 백지에서 시작한다.** 그래서 "무엇을 어디에 적어두는가"가 곧 협업의 품질이다.
한 파일에 다 넣으면 실패한다 — 매 세션 로딩되는 파일에 회차 기록을 쌓으면 토큰이 터지고, 반대로 진행상황을 안 적으면 다음 세션이 이미 끝난 일을 다시 집는다.

**그래서 수명과 갱신 주체가 다른 3개 층으로 나눈다.**

| 층 | 어디에 | 무엇을 담나 | 수명 | 누가 쓰나 | git |
|---|---|---|---|---|---|
| **① 정본** | `CLAUDE.md` | 정체성·**노스 스타**·구조·설계 헌장·**gotcha**·작업 규칙 | 프로젝트 전체 | 사람 + Claude(세션 마감) | ✅ 추적 |
| **② 시간축** | `CLAUDE.local.md` | **회차 기록**(커밋 해시)·다음 후보(**전술**)·미커밋 잔여 | 수개월 | Claude(세션 마감) | ❌ **gitignore** |
| **③ 사람** | `~/.claude/projects/<slug>/memory/` | 사용자 선호·피드백·프로젝트 제약 | 사용자 수명 | Claude(자동, 대화 중) | ❌ (Claude 홈) |

**핵심 분업**:
- ①②는 **의도적으로 쓴 것만** 남는다 → 정확하지만 **구멍이 생긴다**(세션이 끊기거나, 마감 체크리스트를 깜빡하면).
- ③은 **자동으로** 쌓이지만 **사람에 붙는 사실 전용**이다 — 저장소의 진행상황을 대신 기억해 주지 않는다. (§5)
- → 그래서 ①②의 구멍을 막는 유일한 장치는 **🔒 세션 마감 체크리스트(§4)** 이고, 이미 난 구멍은 **git log(1차 사료)로 소급 재구성**한다 — §4 의 사고가 실제로 그렇게 복구됐다.

### 🎯 노스 스타 — 이 패턴의 심장

`CLAUDE.md` §1 에 **"이 프로젝트가 끝내 무엇이 되는가"** 를 한 문장으로 못박는다.

- **없으면**: Claude 는 눈앞의 티켓에 몰입한다. 요청대로 만들지만, 국소 최적해가 쌓여 3개월 뒤 "왜 이렇게 됐지?"가 된다.
- **있으면**: 모든 설계 판단에 공통 분모가 생긴다. **"요청대로 해도 되지만, 노스 스타 기준으론 이 방향이 맞습니다"** 라는 역제안이 나온다.

> 한 줄 요약: **북극성은 "지금 뭘 할까"가 아니라 "지금 이걸 하는 게 맞나"에 답한다.**

갱신 규율: 목표 자체는 거의 안 바뀐다. 하지만 그 아래 **"현재 위치"·"다음 벽"은 회차마다 움직인다** — 세션 마감에서 갱신하지 않으면 이 블록은 즉시 거짓말이 된다.

## 2. 셋업 (5분)

**① 키트를 통째로 새 프로젝트에 복사한다** (셋업 후에도 규칙서로 계속 쓰므로 폴더째 옮긴다):

```bash
NEW=/path/to/새프로젝트
KIT=/path/to/bootstrap-kit      # ← 이 키트의 원본 위치. 머신마다 다르니 확인하고 채운다

mkdir -p "$NEW/_docs"
cp -R "$KIT" "$NEW/_docs/bootstrap-kit"
```

> ⚠️ **경로는 각자 챙긴다.** 이 키트는 어느 머신·어느 저장소에 두든 동작하도록 **절대경로를 못박지 않는다** — 위 `KIT` 은 지금 이 README 가 들어 있는 폴더다. 남의 머신에서 그대로 실행하면 조용히 실패하므로, **복사 전에 실제 위치를 확인**한다(§0 Step 1 이 Claude 에게 같은 것을 지시한다).

**② 새 프로젝트에서 Claude Code 를 열고 한 줄만 시킨다** — 나머지는 §0 의 지시를 따라 Claude 가 수행한다:

```
_docs/bootstrap-kit/README.md 를 읽고 §0 대로 이 저장소를 셋업해줘.
```

> Claude 는 §0 Step 1~9 을 따라 **템플릿 복사 → gitignore → 저장소 탐색 → 테스트 실행 → 노스 스타 질문 → 미사용 섹션 삭제 → 추천 스킬(§9) 설치 → 루프 모드 확인(선택, §10) → 보고** 순으로 진행한다.
> **노스 스타(§1)는 코드에서 유추할 수 없으므로 반드시 너에게 물어본다** — 그 답이 이 패턴의 절반이다.

> ⚠️ **빈 섹션을 형식으로 남기지 마라.** 내용 없는 헤딩은 매 세션 토큰만 먹고 판단을 돕지 않는다. 1일차엔 §1·§2·§8 만 있어도 충분하고, 나머지는 **쓸 게 생겼을 때** 자란다.

## 3. `CLAUDE.md` 구성 규칙 (정본)

**분량 감각: 10~15KB.** 넘으면 상세는 `_docs/` 로 빼고 여기엔 **인덱스만** 남긴다. 이 파일은 매 세션 전량 로딩된다.

| § | 섹션 | 왜 있나 | 없으면 |
|---|---|---|---|
| 1 | 정체성 + **🎯 노스 스타** + 상태줄 | 모든 판단의 공통 분모 | 국소 최적해가 쌓인다 |
| 2 | 개발 명령어 | 환경 규약을 첫 줄에 못박기 | 매번 venv/패키지매니저가 어긋난다 |
| 3 | 구조 — 무엇이 어디에 | **경계와 계약**(트리 아님) | "왜 여기 있는가"를 매번 재조사 |
| 4 | 설계 결정 + **확장 사다리** + **설계 헌장** | 새 기능이 코어를 갉아먹는 걸 막음 | 6개월 뒤 코어가 걸레 |
| 5 | **gotchas** | 같은 함정에 두 번 안 빠지기 | 30분짜리 삽질의 무한 재방문 |
| 6 | 검증 상태 / 다음 후보(**전략**) | "무엇이 잠겨 있고 무엇이 안 됐나" | Green Checkmark 착시 |
| 7 | 문서 인덱스 | 열지 말지 30초 판단 | `_docs/` 가 무덤이 된다 |
| 8 | 작업 규칙 + **세션 마감 동기화** | 협업 규율의 명문화 | §4 참조 |

> 🧭 **"다음 후보"가 두 파일에 있는 이유** — 이름이 같아서 헷갈리지만 **다른 것**이다. 같은 목록을 양쪽에 복사하면, 한쪽만 갱신되는 순간 **둘 다 못 믿게 된다**(이 README §6 안티패턴 "수치 3중 기재"와 같은 형태).
>
> | | `CLAUDE.md` §6 | `CLAUDE.local.md` 🔜 |
> |---|---|---|
> | 무엇 | **전략 로드맵** — "어디로 가는가" | **전술 목록** — "다음 세션에 뭘 집는가" |
> | 수명 | 수개월. 잘 안 바뀐다 | 회차마다. **직전 회차 것만 유효** |
> | 정본 | ✅ 로드맵의 정본 | ❌ 파생 — 어긋나면 §6 을 믿는다 |
> | 번호 | **바꾸지 않는다** — 다른 문서가 "후보 3" 처럼 인용한다 | 자유 |
>
> **판별: 다음 한 회차에 끝나면 local, 몇 회차를 걸치면 §6.** (자율 루프 모드를 켰다면 그 위에 한 층이 더 있다 — 작업 선택의 정본은 `BACKLOG.json` 이고 §6 은 사람용 요약이다. §10)

### 세 가지 장치 (이 템플릿의 실질)

**🪜 확장 사다리** (§4) — `설정 < 플러그인 등록 < 어댑터 < 스키마 확장 < 코어 수정`
"새 기능 = 코어 수정"이 기본값이 되면 코어는 반년 만에 무너진다. 사다리는 Claude 에게 **"가장 싼 칸부터 시도하고, 안 되는 이유를 대라"** 를 강제한다.

**📜 설계 헌장** (§4) — 5~8개의 불변 원칙. 새 기능 리뷰 때 항목마다 O/X 를 매기는 **체크리스트로 쓴다**. 8개를 넘으면 아무도 안 본다.
거의 모든 프로젝트에 유효한 1항: **Loud-failure — 미지 키·오탈자·미주입은 명시적 에러로 죽인다. silent 금지.**

**🕳️ gotchas** (§5) — **최고 ROI 섹션.** 규칙은 단 하나: **한 번 30분 이상 태운 함정은 무조건 등재한다.**
형식은 **증상 → 진짜 원인 → 대응** + 실측 날짜. 원인 없이 대응만 적으면 응용이 안 된다. 고쳐서 영구히 사라진 함정은 **삭제한다**(사료는 git 이 갖고 있다).
쓸 때 두 가지를 지킨다 — **번호는 바꾸지 않는다**(다른 문서가 "gotcha 7" 처럼 인용한다. 새 함정은 뒤에 추가), 그리고 **사건의 모양이 아니라 재발 조건으로 쓴다.** 후자가 특히 잘 무너진다: 경보를 "매크로를 *추가*할 때"로 좁게 적어 둔 동안 같은 원인의 *필드 추가*가 **세 번** 그물을 통과했다. 적어야 할 것은 "이번에 뭘 하다 걸렸나"가 아니라 **"어떤 조건이 갖춰지면 또 걸리나"** 다.

### 문서 저장 위치 — `_docs/` 와 `docs/`

`CLAUDE.md` §8 에 그대로 들어있다. 요지는 **판단 주체를 가르는 것**이다:

| | `_docs/` | `docs/` |
|---|---|---|
| 무엇 | **작업 산출물** — 사람과 Claude 가 개발하며 만든 계획·조사·분석·결정·보고 전부 | **프로젝트의 정식 결과물** — 외부에 그대로 내보낼 수 있는 것 |
| 누가 쓰나 | **Claude**(기본 저장 위치) | **사람** — `_docs/` 에서 선별해 `git mv` 로 승격 |
| git | ✅ 추적 | ✅ 추적 |

**Claude 는 `docs/` 에 새 파일을 만들지 않는다.** 둘이 한 폴더에 섞이면 "내보낼 수 있는 것"과 "우리끼리의 중간 기록"이 구분되지 않고, 그 구분은 **사람만 내릴 수 있는 판단**이다. 문서 타입(ADR·REPORT·NOTE …)은 위치를 가르지 않는다 — 전부 `_docs/` 에 만들고, 승격은 나중에 사람이 한다.

### 문서 프론트매터 (R1~R4)

`CLAUDE.md` §8 에 그대로 들어있다. 요지는 **"문서를 열지 말지 30초 안에 판단하게 하는 장치"**:
- **R1** `related_docs` 는 **저장소 루트 기준 경로** + 항목마다 "왜 관련 있는지" 한 줄
- **R2** `description` **첫 문장에 결론**(질문 말고 답)
- **R3** `status` 는 프론트매터가 정본(`draft`/`active`/`superseded`/`rejected`/`archived` — §9 `doc-writer` 와 동일 어휘), 인덱스의 🟢🟡는 파생
- **R4** `updated` 는 **실질 변경 시만** — `created`↔`updated` 격차가 "살아있다"는 유일한 신호

## 4. `CLAUDE.local.md` 운영 규칙 (시간축) — 세션 마감 루프

**이 파일의 유일한 목적: 다음 세션의 첫 10분을 사는 것.**

### 🔒 세션 마감 체크리스트 (커밋·실질 작업을 만든 세션은 종료 전 필수)

1. **회차 기록** — `## ✅ YYYY-MM-DD(N차)` 섹션 추가, **커밋 해시 포함**. 직전 회차의 해소된 "미커밋"·"다음 후보"는 **같은 편집에서** `→ ✅ N차 완료` 로 정정.
2. **수치 정본은 루트 `CLAUDE.md` 1곳** — 테스트 수 같은 변하는 수치는 루트를 갱신하는 게 본체. 여기엔 회차 스냅샷(델타)만. 옛 회차의 수치는 **손대지 않는다**(사료).
3. **루트 `CLAUDE.md` 동기화** — §1 상태줄·§3·§6·§7 에 이번 작업이 반영됐는지 확인. **같은 사실이 두 값이면 그 자리에서 정정.**
4. **함정 등재** — 이번 세션에 밟은 함정 중 **조건이 재현되면 또 걸릴 것**을 루트 `CLAUDE.md` §5 에 올린다.

> **4항이 따로 있는 이유**: `CLAUDE.local.md` 는 커지면 아카이브로 빠지지만 **`CLAUDE.md` §5 는 매 세션 로딩된다.** 그래서 **회차 기록에만 적는 것은 등재가 아니다** — 실제로 한 함정이 "gotcha N 계열"이라고 회차 기록에만 적힌 채 원장에 안 들어갔고, **다음 세션이 같은 함정을 다시 밟았다.** 판별은 하나다: *"이 작업에만 있나, 조건이 재현되면 또 걸리나."*

> **이 체크리스트는 사고 후에 생겼다.** 원본 프로젝트의 20차 세션이 22커밋을 하고도 `CLAUDE.local.md` 를 안 건드린 채 닫혔다. 다음 세션은 19차의 "미커밋" 표기를 믿고 **이미 끝난 작업을 다시 집을 뻔했다.** 회차 기록은 git log 로부터 소급 재구성해야 했다.
>
> 교훈: **커밋만 하고 문서를 안 건드린 채 세션을 닫는 것이 금지 패턴이다.**

### 회차 기록에 반드시 들어갈 것

- **발단** — 사용자 요청이 뭐였는지 한 줄. (**6개월 뒤 가장 먼저 증발하는 정보다.**)
- **커밋 해시** — 1차 사료. 문서가 틀려도 해시는 안 틀린다.
- **검증 델타** — `264 → 372 passed (+108: io_contract 38, arithmetic 복귀 26 …), 깨짐 0`
- **잔여 미커밋** — 무엇이 **왜** 남았는지. 이게 다음 세션의 첫 질문이다.
- **다음 후보(전술)** — 노스 스타의 "다음 벽"과 정렬. **직전 회차 것만 유효**하고, 옛 목록엔 `⚠️ 대체됨` 을 박는다.
  여기 적는 것은 **다음 세션에 집을 것**이지 로드맵이 아니다 — 몇 회차를 걸치는 항목은 `CLAUDE.md` §6 에 쓴다(이 README §3 의 비교표).

### ⚠️ gitignore 라서 유일본이다 — 아카이빙 규칙

`CLAUDE.local.md` 는 git 이 지켜주지 않는다. 그래서 **아카이브로 분리하는 순간이 이 파일의 유일한 위험 구간**이다.

**발동 조건**: 회차 섹션이 **6개를 넘거나** 파일이 **40KB 를 넘을 때**(실측치 — 그 이상 쌓이면 매 세션 로딩 비용이 회차 기록의 값어치를 넘어선다).

**순서 — 이 4단계를 붙여서 하지 마라.**

1. **아카이브 파일을 먼저 만든다** — `_docs/_archive/HANDOFF-CLAUDE-LOCAL-ARCHIVE-{YYYY-MM-DD-HHMM}.md`(타입 `handoff`, `status: archived`). **원문 그대로** 옮긴다(요약·윤문 금지, 옛 수치도 당시 값 그대로 — *그때 그렇게 적혔다는 사실*이 기록의 가치다).
2. **`diff` 로 무손실을 확인한다** — 눈으로 훑는 것은 확인이 아니다. 복구가 없는 파일이다.
3. **그 다음에** 원본에서 잘라낸다. 잘라내기와 붙여넣기를 한 번에 하지 않는다.
4. **📚 목록에 링크 한 줄을 남긴다** — `- **N차 ~ M차** (기간 · 그 구간의 주제) → [경로](경로)`.

> **왜 `HANDOFF` 타입인가**: 이 아카이브의 **1차 독자는 다음 세션의 Claude** 다 — 과거 결정의 배경·시행착오·커밋 해시를 되짚으러 오는 자리이므로, 개인 메모(`NOTE`)가 아니라 세션 간 인계(`HANDOFF`)가 성격에 맞다. 위치는 타입과 무관하게 `_docs/` 아래이고(§3 "문서 저장 위치"), 아카이브이므로 `_archive/` 하위다.

> **4번이 규칙인 이유**: 링크가 없으면 아카이브는 **만들어지는 순간 아무도 못 찾는 파일**이 된다. 분리는 삭제가 아니라 보존이고, 보존의 값어치는 *되찾을 수 있을 때만* 생긴다. 링크 한 줄에 **회차 범위·기간·주제**를 넣어야 여러 편이 쌓였을 때 어느 것을 열지 고를 수 있다(파일명만으론 못 고른다).

## 5. 자동 기억 — ③ auto memory

①② 는 **사람이 의도적으로 쓴 것만** 남는다. 세션이 갑자기 끊기거나 마감을 깜빡하면 구멍이 생긴다 — 그 구멍을 메우는 자동 장치는 없다고 가정하라. **막는 것은 세션 마감 체크리스트(§4), 이미 난 구멍은 git log(1차 사료)로 소급 재구성**이 정답이다. ③ auto memory 는 그와 별개의 층이다: **저장소가 아니라 사람에 붙는 사실**을 자동 축적한다.

### ③ Claude Code auto memory (내장 — 설치 불필요)

Claude 가 대화 중 **자동으로** `~/.claude/projects/<프로젝트-slug>/memory/` 에 사실을 파일 하나당 하나씩 적는다. `MEMORY.md` 가 인덱스이며 **매 세션 컨텍스트에 로딩**된다.

| `type` | 무엇을 | 예시 |
|---|---|---|
| `user` | 사용자가 누구인가(역할·전문성·선호) | "한국어 존댓말 선호, 기술용어는 원형 유지" |
| `feedback` | **작업 방식에 대한 지시**(교정·확인된 접근) — **왜**를 반드시 포함 | "'프로세스 실행' = API 서버 memory 모드로 기동까지" |
| `project` | 코드·git 이력에서 유추 불가능한 목표·제약 | "당분간 `src/` 폴더만 커밋" |
| `reference` | 외부 리소스 포인터(URL·티켓·대시보드) | |

**활용 지침 — `CLAUDE.md` 와 역할이 겹치지 않게 라우팅한다**:

| 이런 사실은 | 여기에 | 왜 |
|---|---|---|
| "이 코드는 이렇게 동작한다" | **`CLAUDE.md`** (git 추적, 팀 공유) | 코드의 성질이지 사용자의 성질이 아니다 |
| "나는 이런 식으로 일하는 걸 선호한다" | **auto memory** `feedback` | 저장소가 아니라 **사람**에 붙는 사실 |
| "이번 주엔 X 만 커밋한다" | **auto memory** `project` | 코드에 안 남는 한시적 제약 |
| "20차에 22커밋 했다" | **`CLAUDE.local.md`** | 시간축 |

> 📌 **auto memory 에 코드 구조를 적지 마라.** 저장소가 이미 기록하는 것(구조·과거 수정·git 이력·CLAUDE.md 내용)은 중복이고, 코드가 바뀌면 조용히 거짓이 된다. 메모리는 **"코드를 봐도 알 수 없는 것"** 전용이다.
>
> 📌 recall 된 메모리는 **쓰인 시점의 사실**이다. 파일·플래그·함수를 언급하면 **지금도 존재하는지 확인하고** 인용한다.
>
> 📌 이 밖의 세션 자동 기록 도구(예: `remember` 류 플러그인)를 쓰는 환경이라면 그건 **키트 밖의 개인 설정**이다 — 알아서 백그라운드로 돌 뿐, 키트의 운영(마감 체크리스트·회차 기록)은 그것에 의존하지 않고, 그 요약을 정본으로 인용하지도 않는다.

| **낡은 gotcha 방치** | 고쳐진 함정이 계속 경고 중 | 사라진 함정은 **삭제**(git 이 사료를 보관) |
| **CLAUDE.local.md 커밋** | PR 에 진행 메모가 섞이고 팀원과 충돌 | `.gitignore` |
| **이해 없이 자동화** | 손으로 안 해본 작업을 백로그에 올림 → 헐거운 `verify` 로 빠르고 자신만만한 쓰레기 | 먼저 손으로 2~3번 돌려 명세를 뽑은 뒤 `verify` 작성(§10 "verify 는 손에서 나온다") |
| **루프맥싱** | verify 없는 백로그로 회차 반복 → 판정 불가라 영원히 돌며 토큰만 소각 | `verify` 필수 + 매 회차 보고를 사람이 게이트(§10 HITL) |
| **자가 선언 통과** | verify 실행 없이 `passes: true` → 루프가 거짓 완료로 수렴 | `evidence` 의무 — 실행이 없으면 적을 내용이 없다(§10) |
| **백로그 개서** | 어려운 항목을 지우거나 완화해 done 을 위조 | 루프 중 기존 항목 수정·삭제 금지, 추가만 허용(§10) |
| **승인 없는 커밋** | 회차가 보고 없이 커밋까지 내달림 → 사람 검토 지점이 사라짐 | 회차의 끝은 커밋이 아니라 **보고**(§10 HITL — PROMPT.md 가드레일) |

## 7. 셋업 검증 (이게 되면 성공)

새 프로젝트에서 아래 6개가 사실이면 패턴이 이식된 것이다(마지막 **루프 테스트**는 루프 모드를 쓸 때만 — 안 쓰면 5개).

- [ ] **노스 스타 테스트** — Claude 에게 "지금 X 기능을 추가하려는데 어때?" 라고 물었을 때, **노스 스타를 근거로 찬반을 말하는가?** (그냥 만들기 시작하면 §1 이 부실한 것)
- [ ] **gotcha 테스트** — 이미 등재된 함정을 유발하는 명령을 시켰을 때, **Claude 가 먼저 경고하는가?**
- [ ] **마감 테스트** — 커밋을 만든 세션 끝에 Claude 가 **먼저** `CLAUDE.local.md` 회차 기록을 제안하는가? (안 하면 §8 작업 규칙이 안 읽히는 것 — 위치를 앞으로 옮겨라)
- [ ] **재개 테스트** — 새 세션을 열고 **"이어서 하자"** 만 입력했을 때, Claude 가 다음 후보를 정확히 집는가? (이게 이 키트의 최종 목적)
- [ ] **스킬 테스트 — 두 방향을 다 본다** (§9)
  - **시켰을 때**: "이 내용 문서로 정리해줘" 에 `doc-writer` 가 발동하고, 파일명이 `TYPE-주제-YYYY-MM-DD-HHMM.md` 를 따르는가?
  - **안 시켰을 때**: 설계 선택이 걸린 작업을 맡겼을 때, 끝에 **"이 결정은 ADR 로 남길까요?" 를 먼저 묻는가?** — 묻지도 않고 넘어가면 §8 "언제 제안하는가" 가 안 읽히는 것이고, **묻지 않고 만들어 버려도 똑같이 실패**다(승인 게이트가 뚫린 것).
- [ ] **루프 테스트** (루프 모드 시) — 새 세션에 **"PROMPT.md 대로 한 회차 해줘"** 만 입력했을 때, 항목 1개 선택 → `verify` 실제 실행 → 기록(BACKLOG.json·CLAUDE.md·`_docs/`) 갱신 → **회차 보고 정지까지 사람 개입 없이** 도달하고, 승인 없이는 커밋하지 않는가? (§10 — 회차 안의 완결성과 HITL 게이트가 둘 다 검증되어야 한다)

## 8. 한 장 요약

> **`CLAUDE.md` 는 "우리가 누구이고 어디로 가는가"** — 변하지 않는 것. 짧게, git 에.
> **`CLAUDE.local.md` 는 "어디까지 왔는가"** — 회차마다 자란다. 로컬에.
> **auto memory 는 "당신이 누구인가"** — 저장소가 아니라 사람에 붙는다.
> **`BACKLOG.json` + `PROMPT.md` 는 "회차 하나를 통째로 맡기는 법"** — 회차 안은 Claude 가 완결하고, 회차 사이는 사람이 게이트한다(§10 HITL).
>
> 그리고 이 넷을 살아있게 유지하는 단 하나의 습관: **🔒 세션 마감 체크리스트.**

## 9. 📦 추천 스킬 — 신규 프로젝트에서 먼저 깔 것

> 이 키트는 **"무엇을 어디에 적는가"** 를 정의한다. 스킬은 그것을 **실제로 그렇게 적게 만드는 실행 장치**다.
> 셋업 시(§0 Step 6) 이 목록을 설치한다. **목록은 늘어난다** — 새 프로젝트에서 반복해서 아쉬웠던 스킬이 생기면 여기에 추가한다.
>
> ⚠️ **스킬은 실행 경로이되 하드 의존은 아니다.** 설치돼 있으면 `CLAUDE.md` §8 문서 규율이 **모든 문서 작성을 그 스킬로 보낸다**(사용자 요청분 + Claude 가 스스로 제안해 승인받은 분). 설치할 수 없는 환경이면 §8 규율 자체가 자립적이므로 손으로 그대로 쓰면 된다 — 루프 운영(세션 마감, §10 회차 모드)은 어느 쪽이든 키트 내 파일과 git 만으로 완결된다.

### `doc-writer` — 문서 산출물의 타입·네이밍·관점 고정

**왜 필요한가.** 이 키트는 `CLAUDE.md`(정본)와 `CLAUDE.local.md`(시간축)만 규정한다. 그런데 프로젝트가 굴러가면 **그 둘에 넣으면 안 되는 것들**(조사 결과, 설계 결정, 진행 보고서, 실행 가이드)이 반드시 쌓인다. 이걸 방치하면 `_docs/` 는 이름 규칙 없는 파일 더미가 되고, 정본에 넣으면 §1 의 3층 분리가 무너진다. `doc-writer` 는 그 배출구를 **타입별로 규격화**한다.

**어디서 호출되는가.** 키트가 이 스킬을 **부르는 자리는 넷**이다 — `CLAUDE.md` §8 문서 규율(작성 경로 · 언제 제안하는가) · `PROMPT.md` §3 실행 · §6 회차 보고의 "문서 제안" 줄 · §7 승인 후 마감(실제 작성). **사용자가 시킬 때뿐 아니라 Claude 가 스스로 "남겨야 한다"고 판단한 문서**도 이 경로를 탄다.

> ✋ **단, 판단이 곧 생성은 아니다 — 스킬의 확인 규칙은 그대로 살려 둔다.** 이 스킬에는 *"문서로 남길까요?"* 를 먼저 묻는 억제 규칙이 있는데, 키트는 그것을 덮지 않는다. **Claude 가 갖는 것은 파일을 만들 권한이 아니라 제안할 의무다** — 자율 회차에서 판단이 그대로 생성이 되면 `_docs/` 는 아무도 안 읽는 ADR 로 불어나고, §7 인덱스와 매 세션 로딩이 같이 무거워진다.
>
> **자율 회차에서 그 확인을 받는 자리는 §6 회차 보고다** — 회차 안에는 물어볼 사람이 없으므로, 문서를 만들지 않고 보고의 **"문서 제안"** 줄에 올린 뒤 **§7 마감에서 승인된 것만 쓴다.** 커밋 승인과 같은 게이트에 문서 승인을 붙인 것이고, 그래서 "회차의 끝은 커밋이 아니라 보고다" 라는 §10 의 원칙이 문서에도 그대로 적용된다.

**무엇을 하는가.**
- **저장 위치 고정 — Claude 는 `_docs/` 에만 쓴다.** `docs/` 는 프로젝트의 **정식 결과물**만 두는 자리이고, 무엇을 그리로 올릴지는 **사람이 선별**해 `git mv` 로 승격한다. 이 한 줄이 있어야 "외부에 그대로 내보낼 수 있는 것"과 "우리끼리의 중간 기록"이 한 폴더에서 섞이지 않는다. 승격 판단을 Claude 에게 맡기지 않는 것이 요점이다 — 판단은 사람이 하고 Claude 는 자리를 지킨다.
- **3문서군 분류** — 협업 문서(PRD·STRATEGY·PLAN·RESEARCH·ANALYSIS·ADR) / 전달 문서(REPORT·DOCUMENTATION·GUIDE — 외부 전달 가능 수준으로 작성) / 개인 메모(NOTE). **분류는 관점·품질 기준을 정할 뿐, 저장 위치를 가르지 않는다**(전부 `_docs/`).
- **아카이브 처리**(스킬 §9) — **아카이브는 타입이 아니라 상태다.** 수명이 끝난 문서는 원래 타입·파일명을 그대로 둔 채 `status: archived` 로 바꾸고 그 문서가 있던 자리의 `_archive/`(`_docs/_archive/`)로 옮긴다. 이름을 바꾸면 기존 `related_docs` 링크가 전부 깨지고, 본문을 손보면 기록이 아니라 위조가 된다.
- **네이밍·프론트매터 강제** — 파일명 `{TYPE}-{주제}-{YYYY-MM-DD-HHMM}.md`, 프론트매터 필수 `type`·`audience`·`created`·`status`·`description` / 선택 `related_docs`·`updated`.
  **이 규격이 정본은 doc-writer 쪽이다.** 키트 템플릿의 `CLAUDE.md` §8 문서 규율(R1~R4)은 그 규격을 그대로 따르도록 맞춰져 있다 — 특히 `status` 는 **`draft`·`active`·`superseded`·`rejected`·`archived` 5종**으로 양쪽이 동일하다. 스킬을 업데이트해 규격이 바뀌면 **`CLAUDE.md` R3 을 스킬 쪽에 맞춰 고쳐라**(반대 방향이 아니다). 두 어휘가 갈리면 인덱스의 🟢/🟡 파생 표시가 곧 어긋난다.
- **고정 템플릿 없음** — 타입별 Persona 관점만 주고 문서 형태는 상황에 맞춘다.
- **오작동 억제** — "분석해줘"·"조사해봐" 처럼 **대화로 답하면 되는 요청엔 문서를 만들지 않는다.**

**설치 (Claude 가 §0 Step 6 에서 수행)**

> ⚠️ **이 스킬은 키트에 동봉돼 있지 않다 — 사용자가 직접 챙긴다.** 폴더째 복사해도 따라오지 않으므로, **Claude 는 설치 여부를 확인하고 없으면 반드시 알린다**(추측해서 만들지 말 것 — §0 Step 6).

```bash
SKILLS=/path/to/doc-writer      # ← 원본 위치. 머신마다 다르니 사용자에게 확인한다

cp -r "$SKILLS" ./.claude/skills/    # 프로젝트 전용
cp -r "$SKILLS" ~/.claude/skills/    # 또는 모든 프로젝트에서 쓰려면 (사용자 전역)
```

- **Claude 의 책임은 알림까지다**: `~/.claude/skills/doc-writer` 와 `./.claude/skills/doc-writer` 를 확인해 **둘 다 없으면 "doc-writer 가 없다. 원본 경로를 알려주면 설치하겠다" 를 명시적으로 보고**한다. 조용히 넘어가면 문서 규율이 첫날부터 안 걸린다.
- 구성 파일 3개: `SKILL.md` · `references/writing-principles.md` · `references/personas.md` — **폴더째** 복사한다(references 를 빠뜨리면 문체·관점 규칙이 통째로 사라진다).
- 이미 `~/.claude/skills/doc-writer` 가 있으면 **다시 깔지 않는다** — 전역 설치가 프로젝트 복사본보다 유지보수가 쉽다.
- 설치 확인: 새 세션에서 `/` 목록에 뜨는지, 또는 "이 내용 문서로 정리해줘" 에 반응하는지(§7 스킬 테스트).

## 10. 🔁 루프 엔지니어링 — 키트를 자율 하네스로 확장하기

> **루프 엔지니어링**: 에이전트에게 매 프롬프트를 사람이 치는 대신, **에이전트를 대신 굴리는 시스템을 설계**하는 것.
> 측정 가능한 목표를 정하면 러너가 **매 회차 새 컨텍스트**의 에이전트를 기동하고, 에이전트는 디스크에서 상태를 읽고 → 한 단위의 일을 하고 → 검증하고 → 상태를 파일에 되써놓고 → 종료한다. 목표 충족 또는 한도 도달까지 반복.
> (2026년 표준 패턴 — Anthropic 의 long-running agent 하네스, Huntley 의 Ralph 루프, Claude Code 네이티브 `/goal` 이 전부 이 구조다. 출처는 이 절 끝.)
>
> **이 키트는 그 개념에서 "회차 내부의 자기완결성"만 가져오고, 회차 경계는 사람이 잡는다(HITL).** 회차 안은 Claude 가 실행→검증→기록→보고까지 개입 없이 완결하지만, 커밋과 다음 회차 진행은 매번 사람이 보고를 검토하고 결정한다. 무인 반복이 목적이 아니라 **"한 번 시키면 한 회차를 통째로 믿고 맡길 수 있는 상태"** 가 목적이다. 그리고 이 운영은 **키트 내 파일과 git 만으로 돈다** — 외부 스킬·플러그인 의존이 없다.

### 이 키트는 이미 루프의 절반이다

| 루프 엔지니어링 개념 | 이 키트의 기존 대응물 |
|---|---|
| 목표(goal) | `CLAUDE.md` §1 노스 스타 + "다음 벽" |
| 진행 파일(progress file) | `CLAUDE.local.md` 회차 기록 (커밋 해시·검증 델타) |
| 회차 간 상태 되쓰기(write-back) | 🔒 세션 마감 체크리스트 (§4) |
| 1회차 = 1단위 작업 | 회차(N차) 규율 |
| 지식 축적 | gotchas(§3) · ADR(문서 규율 — `CLAUDE.md` §8) · auto memory(§5) |
| 세션 시작 상태 복원 | 재개 테스트(§7) — `CLAUDE.local.md` 헤더·최신 회차 + git log |

빠져 있던 것은 둘이다: **① 기계가 판정할 수 있는 백로그**(노스 스타는 사람용 문장이라 pass/fail 이 안 나온다), **② 매 회차 동일하게 주입되는 프로토콜**("이어서 하자" 한 줄보다 정밀하게 — 회차의 읽기 순서·완결 기준·정지 지점을 고정한다). 루프 모드의 추가 2파일이 정확히 그 둘이다:

| 파일 | 복사 후 | 역할 | git |
|---|---|---|---|
| `BACKLOG.template.json` | `<프로젝트>/BACKLOG.json` | **목표 계약** — `verify` 가 달린 항목 목록 + `done_when` 종료 조건 | ✅ 추적 |
| `PROMPT.template.md` | `<프로젝트>/PROMPT.md` | **회차 헌법** — 읽기→선택→실행→검증→기록→보고(HITL 정지) 프로토콜 | ✅ 추적 |

### 좋은 `verify` 는 책상이 아니라 손에서 나온다

항목의 `verify` 를 노스 스타에서 곧장 받아쓰지 마라 — 그 작업을 **먼저 손으로 2~3번 돌려본 뒤에** 쓴다. 수동 실행이 "무엇이 done 인가"와 "어디서 틀리는가"를 드러내고, **그 관찰이 곧 `verify` 의 명세**다(설명할 수 없는 프로세스는 자동화할 수 없다). 머릿속에서 지어낸 검사는 대개 헐거워서, 모델이 제 기준으로 통과시키고(자기채점, §6) 루프는 쓰레기를 내며 "통과"를 반복한다. 키트가 §6 에서 되풀이 경고하는 **루프맥싱(판정 불가로 영원히 돎)의 예방책이 바로 이 수동 리허설**이다 — `origin: "discovered"` 로 새 항목을 넣을 때도 판정 기준을 손으로 확인하기 전엔 `verify` 칸을 비워둔다.

### 왜 백로그가 JSON 인가, 왜 항목 수정 금지인가

Anthropic 실측: 에이전트는 Markdown 목록보다 **JSON 파일을 함부로 고쳐 쓸 확률이 낮다.** 그리고 자율 루프의 최대 실패 모드는 코드가 아니라 **목표 쪽을 움직여서 "done" 을 만드는 것**이다(어려운 항목 삭제, verify 완화, 테스트 약화). 그래서 계약 규칙이 세 개다:

1. 루프 중 Claude 가 만질 수 있는 필드는 `passes` / `evidence` / `attempts` 뿐. 항목 추가는 `origin: "discovered"` 로만, **기존 항목의 수정·삭제는 사람의 권한**이다.
2. **`verify` 없는 항목은 백로그 자격이 없다** — 판정 불가능한 항목은 루프를 영원히 돌게 만든다(루프맥싱, §6). 쪼개거나 판정 기준을 합의해서 넣는다.
3. `passes: true` 는 verify **실제 실행 + `evidence` 기록** 없이는 금지 — 자가 선언 통과(§6)를 구조로 막는다.

### 회차 프로토콜 (PROMPT.md 의 요약 — 정본은 그 파일)

```
읽기 (CLAUDE.md → CLAUDE.local.md → BACKLOG.json → git log → 테스트 기준선 green 확인)
→ 항목 1개 선택 (막는 것·위험한 것 먼저, attempts≥2 는 STUCK)
→ 실행 (확장 사다리 순서 · 결정은 ADR 로 · 함정은 gotcha 로)
→ 검증 (verify 실제 실행 — 실행 없는 passes 금지, 실패는 실패대로 보고)
→ 기록 (BACKLOG → CLAUDE.md 상태줄·§6 → _docs/ 산출 문서)
→ 🙋 회차 보고에서 정지 (상태 태그 · 검증 증거 · diff 요약 · 커밋 메시지 초안 · 다음 후보)
→ [사람] 검토 · 결정 → 승인 시: 커밋 + CLAUDE.local.md 마감 기록(커밋 해시) → 회차 종료
```

핵심 원리는 **매 회차 새 컨텍스트**다. 긴 세션 하나보다 짧은 회차 여럿이 낫다 — 컨텍스트가 썩지 않고, 각 회차가 사람이 검토한 클린 커밋으로 끝나므로 실패해도 오염이 다음 회차로 번지지 않는다. 그리고 "문서가 곧 기억"이라는 이 키트의 전제가 루프에서는 문자 그대로 강제된다: **안 적으면 다음 회차의 나는 모른다.** 세션 마감 체크리스트(§4)가 사람 협업에선 습관이지만 루프에선 생존 조건인 이유다.

### 운영 사이클 — 러너는 사람이다 (HITL)

| 단계 | 누가 | 무엇 |
|---|---|---|
| ① 회차 시작 | 사람 | (권장: 새 세션에서) **"PROMPT.md 대로 한 회차 해줘"** 한 줄 |
| ② 회차 수행 | Claude | 읽기→선택→실행→검증→기록까지 **개입 없이 완결**, 회차 보고에서 정지 |
| ③ 검토·결정 | 사람 | 보고 확인 → 커밋 승인 / 수정 지시 / 백로그 조정 / 중단 |
| ④ 마감 | Claude | 승인 시 커밋 + `CLAUDE.local.md` 회차 기록(커밋 해시) |
| ⑤ 반복 | 사람 | 다음 회차 시작 — 🏁 DONE 보고가 나올 때까지 |

> **검토(③단계)의 핵심은 승인이 아니라 검증기를 조이는 것이다.** 회차가 "통과"를 보고했는데 산출물이 미덥잖으면, 그건 승인 신호가 아니라 **`verify` 가 헐겁다는 신호**다 — 커밋을 승인하기 전에 백로그의 `verify` 를 조인다(예: 루프가 테스트를 약화시켜 통과했다면 "테스트 파일 수정 금지 + 미변경 확인"을 verify 에 추가한다). 모델이 똑똑해지는 게 아니라 루프가 똑똑해진다 — 이 조이기는 루프 중 **사람만 가진 권한**이다(항목 수정, §"왜 항목 수정 금지인가").

> 이 사이클은 **키트 내 파일(PROMPT.md · BACKLOG.json · CLAUDE.md · CLAUDE.local.md)과 git 만으로 돈다** — 외부 스킬·플러그인·커맨드 의존이 없으므로 어느 프로젝트·어느 머신에서든 그대로 동작한다. 환경에 무인 러너(루프 플러그인, 네이티브 `/goal` 등)가 있다면 ①·⑤를 자동화할 수도 있지만, 그것은 키트 밖의 선택이다 — 그 경우에도 §7 루프 테스트 통과와 **`BACKLOG.json` 의 `budget`(max_rounds·max_wallclock_min) 설정**이 선행 조건이고(사람이 매 회차 잡던 예산·반복 exit 가 사라지므로 — 미설정 시 무한 루프·예산 폭주), ③의 검토를 건너뛰는 만큼 백로그 `verify` 의 품질이 곧 결과물의 품질 상한이 된다.

> **의도적 비목표** (아티클 15·17·18): 이 키트는 회차당 1항목을 **사람 페이스로 순차** 처리한다 — 그래서 비용·모델 라우팅(17)은 사람 게이트 속도에 묶여 자동 최적화 대상이 아니고, 서브에이전트 병렬(18)은 단일 항목 순차 설계와 배치되며, open 루프(탐색·15)는 경계 있는 백로그(closed)와 배치된다. 이것들이 필요할 만큼 규모가 커지면, 그건 이 HITL 키트를 졸업하고 위의 무인 하네스로 갈 신호다.

### 사람이 소환되는 조건 (STUCK)

같은 항목 2회 실패 · 백로그 항목 간 모순 · verify 실행 불가 · done_when 관측 불가 · (무인화 시) `budget` 한도 도달 → 에이전트는 CLAUDE.local.md 에 상황을 기록하고 `STUCK: 사유` 를 출력하고 멈춘다(무한 재시도 금지 — 2회 실패는 접근이 아니라 **문제에 대한 이해 자체가 틀렸다**는 신호다). 이때 사람이 하는 일이 곧 사람의 역할 정의다: **백로그 항목을 수정·분할·포기 처리하는 것**(루프 중 유일하게 사람만 가진 권한).

## 11. 🅾️ 오버레이 모드 — 기존 프로젝트(브라운필드)에 잠깐 얹기

> §0~§10 은 백지(그린필드) 전제다. 이 절은 **이미 상당히 진행된 프로젝트에서 이 kit 로 격리된 시도를 하고 싶을 때** 쓰는 모드다.
> 목적은 기존 `CLAUDE.md` 를 **통째로 갈아끼우고**, 프로젝트의 기존 맥락에 얽매이지 않는 **새 시도**를 하는 것이다 — 그래서 CLAUDE.md 처리는 항상 "완전 교체"이고, 격리는 항상 **워크트리**다.

**왜 브랜치가 아니라 워크트리인가.** CLAUDE.md 를 통째로 교체하는 게 목적이라, 원본을 물리적으로 손대지 않는 워크트리라야 (1) 원본 `CLAUDE.md`·환경이 **무손상**이고 (2) 원본이 git 추적이든 무시든 상관없으며 (3) **teardown 이 한 줄**이다. 브랜치는 CLAUDE.md 파일 하나를 디스크에서 공유해 병행 세션에 맥락이 새고, 복원에 `skip-worktree`·수동 백업 같은 체조가 필요하다.

```bash
# ① 격리 — 워크트리로 새 브랜치를 별 디렉토리에 뽑는다
git worktree add ../<작업이름> -b overlay/<작업이름>
cd ../<작업이름>

# ② 환경 재구성 — 워크트리는 새 폴더라 gitignore 된 것(.venv·node_modules·.env)이 없다
uv sync            # 또는 npm ci — 프로젝트에 맞게. .env 등 시크릿은 원본에서 복사

# ③ 커밋 위생 선등록 — 스캐폴딩을 info/exclude 에 박아 "커밋 안 함"을 습관이 아니라 구조로 만든다.
#    이 파일들은 계속 untracked 로 남아 git add -A 에도 안 딸려오고, 그래서 ⑥ 머지가 코드만 실어나른다.
#    (원본 main 이 CLAUDE.md 를 추적 중이어도 exclude 는 untracked 에만 작동하므로 원본엔 무해.)
printf '%s\n' CLAUDE.md CLAUDE.local.md BACKLOG.json PROMPT.md >> .git/info/exclude

# ④ kit 셋업 — 여기서 §0 을 그대로. CLAUDE.md 는 기존 걸 무시하고 새로 쓴다.
#    원본은 ../<원본폴더> 에 그대로 있으니 손실 위험이 없다.

# ⑤ 작업 — 아래 "수명 비례"대로 필요한 층만 얹는다

# ⑥ teardown — 통째 삭제. gitignore 된 CLAUDE.local.md·스캐폴딩까지 한 번에 사라진다
cd ../<원본폴더>
git worktree remove --force ../<작업이름>
```

**수명 비례 — 얹는 층은 작업 길이에 비례한다** (§2 "빈 섹션 지워라"와 같은 원리. CLAUDE.md 는 이 모드의 전제라 항상 새로 쓴다):

| 작업 규모 | CLAUDE.md | CLAUDE.local.md (롤링) | BACKLOG+PROMPT (루프) |
|---|---|---|---|
| 짧은 시도 (1세션) | 새로 씀 | ❌ | ❌ |
| 여러 세션 | 새로 씀 | ✅ 회차 연속성 | △ 측정목표면 |
| 측정목표 다회차 | 새로 씀 | ✅ | ✅ 루프(§10) |

**커밋 위생**: 워크트리에서 **커밋하는 건 기능 코드뿐이다.** 교체한 `CLAUDE.md`·`CLAUDE.local.md`·`BACKLOG.json`·`PROMPT.md` 는 커밋하지 않는다(작업 폴더에만 두거나 `.git/info/exclude` 에 넣는다) — 그래야 `worktree remove` 로 흔적 없이 사라지고, 아래 머지가 스캐폴딩을 원본에 흘리지 않는다.

**원본에 반영하려면**: `overlay/*` 브랜치(기능 코드 커밋만 담긴)를 원본 main 에 merge/PR 한다 — teardown(`worktree remove`) **전에** 머지해야 한다. 반영할 게 없는 순수 실험이면 그냥 remove 하면 원본에 아무것도 안 남는다.
