# 프로젝트 부트스트랩 키트 — Claude Code 작업 패턴 이식용

**이 폴더의 3파일을 새 프로젝트에 복사하면 셋업이 끝난다.**

| 파일 | 복사 후 이름 | 역할 |
|---|---|---|
| `CLAUDE.template.md` | `<새프로젝트>/CLAUDE.md` | **정본** — 불변의 것(목표·구조·원칙·함정) |
| `CLAUDE.local.template.md` | `<새프로젝트>/CLAUDE.local.md` | **시간축** — 회차 기록·다음 후보 |
| `README.md` (이 파일) | `<새프로젝트>/docs/bootstrap-kit/README.md` | **규칙서 겸 상기용** — 왜 이렇게 만들었는가 |

> **폴더째 복사를 권장한다.** 이 README 는 셋업 1회용이 아니라, **몇 달 뒤 "이 파일들이 왜 이 모양이더라?" 를 상기시키는 근거 문서**다. 신규 프로젝트의 `CLAUDE.md` §8 에서 이 경로를 가리키게 해두면(템플릿에 이미 들어있다) Claude 도 사람도 규칙의 출처를 되짚을 수 있다.

> **출처**: 이 패턴은 발명이 아니라 **추출**이다 — 실제 프로젝트를 6주(20회차) 개발하며 굴러간 실물을 일반화했다. 특히 §4 의 세션 마감 루프는 **실제로 20차 기록이 통째로 누락되는 사고를 겪고 나서** 생긴 방어 장치다.

## 0. 🤖 Claude Code 에게: 셋업을 요청받았다면 이대로 하라

> 사용자가 **"이 README 읽고 셋업해줘"** 라고 하면, 아래를 **순서대로** 실행한다. 이 절은 사람이 아니라 **너에게 하는 지시**다.

**Step 1 — 이 키트의 위치를 먼저 확정한다.** 절대경로를 가정하지 마라. 이 README 가 있는 폴더가 곧 `KIT` 이다.

```bash
# 이 README 의 실제 위치를 찾는다 (저장소 어디에 복사됐든)
find . -name 'CLAUDE.template.md' -not -path '*/node_modules/*' | head -1
```

**Step 2 — 템플릿 2개를 저장소 루트로 복사(이름 변경)하고, gitignore 를 건다.**

```bash
cp -n "<KIT>/CLAUDE.template.md"       ./CLAUDE.md        # -n: 기존 파일 덮어쓰기 방지 — 이미 있어서 복사가 안 됐으면 사용자에게 물어라
cp -n "<KIT>/CLAUDE.local.template.md" ./CLAUDE.local.md
for p in 'CLAUDE.local.md' '.remember/'; do               # ② 시간축은 로컬 전용 (§4) — 중복 등록 방지
  grep -qxF "$p" .gitignore 2>/dev/null || printf '%s\n' "$p" >> .gitignore
done
```

**Step 3 — 저장소를 실제로 탐색한다.** 추측으로 템플릿을 채우지 마라. 최소한 이것들을 **읽고** 사실을 확보한다:
- 패키지 매니저·가상환경 규약(`pyproject.toml`/`package.json`/`uv.lock`/`.venv` 등) → §2
- 진입점·주요 디렉토리의 **경계와 계약** → §3 (`ls` 트리를 옮겨적는 게 아니다)
- 테스트 명령을 **실제로 실행**해서 통과 수를 확인 → §1 상태줄·§6 (**실행 없이 숫자를 쓰지 마라**)

**Step 4 — 채울 수 없는 것은 물어라.** 특히 **§1 노스 스타는 코드에서 유추할 수 없다.** 사용자에게 직접 묻는다:
1. 이 프로젝트가 **끝내 무엇이 되면** 성공인가? (한 문장, 관측 가능한 상태로)
2. 지금 가로막고 있는 **다음 벽**은 무엇인가?
3. 어떤 기능을 추가하든 **절대 훼손하면 안 되는 것**은? (→ §4 설계 헌장의 씨앗)

**Step 5 — 안 쓸 섹션은 지운다.** 신규 프로젝트 1일차엔 **§1·§2·§8 만 남기고 §4~§7 은 통째로 삭제**해도 된다. 내용 없는 헤딩은 매 세션 토큰만 먹고 판단을 돕지 않는다. 섹션은 **쓸 게 생겼을 때 자란다.**

**Step 6 — §9 의 추천 스킬을 설치한다.** 문서 산출물이 나올 프로젝트라면 **`doc-writer` 는 사실상 필수**다(이 키트의 문서 규율 — 네이밍·프론트매터 — 을 강제하는 실행 장치이므로). 이미 설치돼 있으면 건너뛰고, 없으면 §9 의 설치 절차를 따른 뒤 **무엇을 설치했는지 사용자에게 보고**한다. 설치 원본을 찾지 못하면 추측해서 만들지 말고 경로를 물어라.

**Step 7 — 템플릿 안내 주석(`<!-- ... -->`)을 전부 제거한다.** 채운 뒤엔 안내문이 남아 있으면 안 된다.

**Step 8 — 보고한다**: 무엇을 채웠고, 무엇을 **실행해서 확인**했고, 어떤 스킬을 설치했고, 무엇을 사용자 답변 대기로 비워뒀는지.

> ⚠️ **하지 말 것**: 템플릿의 `{중괄호}` 자리를 그럴듯한 추측으로 메우는 것. 이 파일은 **매 세션 로딩되는 정본**이라, 여기 박힌 거짓말은 프로젝트 내내 Claude 를 오도한다. **모르면 비워두고 묻는다.**

## 1. 핵심 아이디어 — Claude 의 기억을 4층으로 쪼갠다

Claude Code 는 **매 세션 백지에서 시작한다.** 그래서 "무엇을 어디에 적어두는가"가 곧 협업의 품질이다.
한 파일에 다 넣으면 실패한다 — 매 세션 로딩되는 파일에 회차 기록을 쌓으면 토큰이 터지고, 반대로 진행상황을 안 적으면 다음 세션이 이미 끝난 일을 다시 집는다.

**그래서 수명과 갱신 주체가 다른 4개 층으로 나눈다.**

| 층 | 어디에 | 무엇을 담나 | 수명 | 누가 쓰나 | git |
|---|---|---|---|---|---|
| **① 정본** | `CLAUDE.md` | 정체성·**노스 스타**·구조·설계 헌장·**gotcha**·작업 규칙 | 프로젝트 전체 | 사람 + Claude(세션 마감) | ✅ 추적 |
| **② 시간축** | `CLAUDE.local.md` | **회차 기록**(커밋 해시)·다음 후보·미커밋 잔여 | 수개월 | Claude(세션 마감) | ❌ **gitignore** |
| **③ 사람** | `~/.claude/projects/<slug>/memory/` | 사용자 선호·피드백·프로젝트 제약 | 사용자 수명 | Claude(자동, 대화 중) | ❌ (Claude 홈) |
| **④ 서사** | `.remember/` (플러그인) | 세션 원자료의 자동 압축·핸드오프 | 자동 회전 | 훅(자동, 무개입) | ❌ gitignore |

**핵심 분업**:
- ①②는 **의도적으로 쓴 것만** 남는다 → 정확하지만 **구멍이 생긴다**(세션이 끊기거나, 마감 체크리스트를 깜빡하면).
- ④는 **자동으로 다 남는다** → 구멍이 없지만 **압축 손실이 있다**(Haiku 요약).
- → **④는 ①②의 빈 곳을 메우는 용도다. 정본으로 인용하지 않는다.** (§5)

### 🎯 노스 스타 — 이 패턴의 심장

`CLAUDE.md` §1 에 **"이 프로젝트가 끝내 무엇이 되는가"** 를 한 문장으로 못박는다.

- **없으면**: Claude 는 눈앞의 티켓에 몰입한다. 요청대로 만들지만, 국소 최적해가 쌓여 3개월 뒤 "왜 이렇게 됐지?"가 된다.
- **있으면**: 모든 설계 판단에 공통 분모가 생긴다. **"요청대로 해도 되지만, 노스 스타 기준으론 이 방향이 맞습니다"** 라는 역제안이 나온다.

> 한 줄 요약: **북극성은 "지금 뭘 할까"가 아니라 "지금 이걸 하는 게 맞나"에 답한다.**

갱신 규율: 목표 자체는 거의 안 바뀐다. 하지만 그 아래 **"현재 위치"·"다음 벽"은 회차마다 움직인다** — 세션 마감에서 갱신하지 않으면 이 블록은 즉시 거짓말이 된다.

## 2. 셋업 (5분)

**① 키트를 통째로 새 프로젝트에 복사한다** (셋업 후에도 규칙서로 계속 쓰므로 폴더째 옮긴다):

```bash
NEW=/path/to/새프로젝트
KIT=/Users/sspark/Work/rules/bootstrap-kit                       # ← 이 키트의 원본 위치 (rules 저장소가 마스터)

mkdir -p "$NEW/docs"
cp -R "$KIT" "$NEW/docs/bootstrap-kit"
```

**② 새 프로젝트에서 Claude Code 를 열고 한 줄만 시킨다** — 나머지는 §0 의 지시를 따라 Claude 가 수행한다:

```
docs/bootstrap-kit/README.md 를 읽고 §0 대로 이 저장소를 셋업해줘.
```

> Claude 는 §0 Step 1~8 을 따라 **템플릿 복사 → gitignore → 저장소 탐색 → 테스트 실행 → 노스 스타 질문 → 미사용 섹션 삭제 → 추천 스킬(§9) 설치 → 보고** 순으로 진행한다.
> **노스 스타(§1)는 코드에서 유추할 수 없으므로 반드시 너에게 물어본다** — 그 답이 이 패턴의 절반이다.

> ⚠️ **빈 섹션을 형식으로 남기지 마라.** 내용 없는 헤딩은 매 세션 토큰만 먹고 판단을 돕지 않는다. 1일차엔 §1·§2·§8 만 있어도 충분하고, 나머지는 **쓸 게 생겼을 때** 자란다.

## 3. `CLAUDE.md` 구성 규칙 (정본)

**분량 감각: 10~15KB.** 넘으면 상세는 `docs/` 로 빼고 여기엔 **인덱스만** 남긴다. 이 파일은 매 세션 전량 로딩된다.

| § | 섹션 | 왜 있나 | 없으면 |
|---|---|---|---|
| 1 | 정체성 + **🎯 노스 스타** + 상태줄 | 모든 판단의 공통 분모 | 국소 최적해가 쌓인다 |
| 2 | 개발 명령어 | 환경 규약을 첫 줄에 못박기 | 매번 venv/패키지매니저가 어긋난다 |
| 3 | 구조 — 무엇이 어디에 | **경계와 계약**(트리 아님) | "왜 여기 있는가"를 매번 재조사 |
| 4 | 설계 결정 + **확장 사다리** + **설계 헌장** | 새 기능이 코어를 갉아먹는 걸 막음 | 6개월 뒤 코어가 걸레 |
| 5 | **gotchas** | 같은 함정에 두 번 안 빠지기 | 30분짜리 삽질의 무한 재방문 |
| 6 | 검증 상태 / 다음 후보 | "무엇이 잠겨 있고 무엇이 안 됐나" | Green Checkmark 착시 |
| 7 | 문서 인덱스 | 열지 말지 30초 판단 | docs/ 가 무덤이 된다 |
| 8 | 작업 규칙 + **세션 마감 동기화** | 협업 규율의 명문화 | §4 참조 |

### 세 가지 장치 (이 템플릿의 실질)

**🪜 확장 사다리** (§4) — `설정 < 플러그인 등록 < 어댑터 < 스키마 확장 < 코어 수정`
"새 기능 = 코어 수정"이 기본값이 되면 코어는 반년 만에 무너진다. 사다리는 Claude 에게 **"가장 싼 칸부터 시도하고, 안 되는 이유를 대라"** 를 강제한다.

**📜 설계 헌장** (§4) — 5~8개의 불변 원칙. 새 기능 리뷰 때 항목마다 O/X 를 매기는 **체크리스트로 쓴다**. 8개를 넘으면 아무도 안 본다.
거의 모든 프로젝트에 유효한 1항: **Loud-failure — 미지 키·오탈자·미주입은 명시적 에러로 죽인다. silent 금지.**

**🕳️ gotchas** (§5) — **최고 ROI 섹션.** 규칙은 단 하나: **한 번 30분 이상 태운 함정은 무조건 등재한다.**
형식은 **증상 → 진짜 원인 → 대응** + 실측 날짜. 원인 없이 대응만 적으면 응용이 안 된다. 고쳐서 영구히 사라진 함정은 **삭제한다**(사료는 git 이 갖고 있다).

### 문서 프론트매터 (R1~R4)

`CLAUDE.md` §8 에 그대로 들어있다. 요지는 **"문서를 열지 말지 30초 안에 판단하게 하는 장치"**:
- **R1** `related_docs` 는 **저장소 루트 기준 경로** + 항목마다 "왜 관련 있는지" 한 줄
- **R2** `description` **첫 문장에 결론**(질문 말고 답)
- **R3** `status` 는 프론트매터가 정본(`draft`/`active`/`superseded`/`rejected`/`archived` — §9 `doc-writer` 와 동일 어휘), 인덱스의 🟢🟡는 파생
- **R4** `updated` 는 **실질 변경 시만** — `created`↔`updated` 격차가 "살아있다"는 유일한 신호

## 4. `CLAUDE.local.md` 운영 규칙 (시간축) — 세션 마감 루프

**이 파일의 유일한 목적: 다음 세션의 첫 10분을 사는 것.**

### 🔒 세션 마감 체크리스트 (커밋·실질 작업을 만든 세션은 종료 전 필수)

1. **회차 기록** — `## ✅ YYYY-MM-DD(N차)` 섹션 추가, **커밋 해시 포함**. 직전 회차의 해소된 "미커밋"·"다음 후보"는 **같은 편집에서** `→ ✅ N차 완료` 로 정정.
2. **수치 정본은 루트 `CLAUDE.md` 1곳** — 테스트 수 같은 변하는 수치는 루트를 갱신하는 게 본체. 여기엔 회차 스냅샷(델타)만. 옛 회차의 수치는 **손대지 않는다**(사료).
3. **루트 `CLAUDE.md` 동기화** — §1 상태줄·§3·§6·§7 에 이번 작업이 반영됐는지 확인. **같은 사실이 두 값이면 그 자리에서 정정.**

> **이 체크리스트는 사고 후에 생겼다.** 원본 프로젝트의 20차 세션이 22커밋을 하고도 `CLAUDE.local.md` 를 안 건드린 채 닫혔다. 다음 세션은 19차의 "미커밋" 표기를 믿고 **이미 끝난 작업을 다시 집을 뻔했다.** 회차 기록은 git log 로부터 소급 재구성해야 했다.
>
> 교훈: **커밋만 하고 문서를 안 건드린 채 세션을 닫는 것이 금지 패턴이다.**

### 회차 기록에 반드시 들어갈 것

- **발단** — 사용자 요청이 뭐였는지 한 줄. (**6개월 뒤 가장 먼저 증발하는 정보다.**)
- **커밋 해시** — 1차 사료. 문서가 틀려도 해시는 안 틀린다.
- **검증 델타** — `264 → 372 passed (+108: io_contract 38, arithmetic 복귀 26 …), 깨짐 0`
- **잔여 미커밋** — 무엇이 **왜** 남았는지. 이게 다음 세션의 첫 질문이다.
- **다음 후보** — 노스 스타의 "다음 벽"과 정렬. **직전 회차 것만 유효**하고, 옛 목록엔 `⚠️ 대체됨` 을 박는다.

### ⚠️ gitignore 라서 유일본이다

`CLAUDE.local.md` 는 git 이 지켜주지 않는다. **아카이브로 분리할 때(파일이 20KB 초과 시)가 유일한 위험 구간**이다 — 반드시 **"아카이브 파일 생성 → 내용 확인 → 그 다음 삭제"** 순서. 잘라내기 한 번에 하지 마라.

## 5. 자동 기억 — 빈 곳을 메우는 두 도구

①② 는 **사람이 의도적으로 쓴 것만** 남는다. 세션이 갑자기 끊기거나 마감을 깜빡하면 구멍이 생긴다. 그 구멍을 메우는 게 아래 둘이다.

### ③ Claude Code auto memory (내장 — 설치 불필요)

Claude 가 대화 중 **자동으로** `~/.claude/projects/<프로젝트-slug>/memory/` 에 사실을 파일 하나당 하나씩 적는다. `MEMORY.md` 가 인덱스이며 **매 세션 컨텍스트에 로딩**된다.

| `type` | 무엇을 | 예시 |
|---|---|---|
| `user` | 사용자가 누구인가(역할·전문성·선호) | "한국어 존댓말 선호, 기술용어는 원형 유지" |
| `feedback` | **작업 방식에 대한 지시**(교정·확인된 접근) — **왜**를 반드시 포함 | "'프로세스 실행' = API 서버 memory 모드로 기동까지" |
| `project` | 코드·git 이력에서 유추 불가능한 목표·제약 | "당분간 `src/` 폴더만 커밋" |
| `reference` | 외부 리소스 포인터(URL·티켓·대시보드) | |

**활용 지침 — `CLAUDE.md` 와 역할이 겹치지 않게 라우팅한다**:

| 이런 사실은 | 여기에 | 왜 |
|---|---|---|
| "이 코드는 이렇게 동작한다" | **`CLAUDE.md`** (git 추적, 팀 공유) | 코드의 성질이지 사용자의 성질이 아니다 |
| "나는 이런 식으로 일하는 걸 선호한다" | **auto memory** `feedback` | 저장소가 아니라 **사람**에 붙는 사실 |
| "이번 주엔 X 만 커밋한다" | **auto memory** `project` | 코드에 안 남는 한시적 제약 |
| "20차에 22커밋 했다" | **`CLAUDE.local.md`** | 시간축 |

> 📌 **auto memory 에 코드 구조를 적지 마라.** 저장소가 이미 기록하는 것(구조·과거 수정·git 이력·CLAUDE.md 내용)은 중복이고, 코드가 바뀌면 조용히 거짓이 된다. 메모리는 **"코드를 봐도 알 수 없는 것"** 전용이다.
>
> 📌 recall 된 메모리는 **쓰인 시점의 사실**이다. 파일·플래그·함수를 언급하면 **지금도 존재하는지 확인하고** 인용한다.

### ④ `remember` 플러그인 (설치형 — 자동 서사)

*(이 머신에서 실측: `~/.claude/plugins/cache/claude-plugins-official/remember/0.8.3` — v0.8.3 이 이미 캐시돼 있다. 단, 설치는 프로젝트별이므로 새 프로젝트에서는 아래 설치 절차가 필요할 수 있다.)*

**무엇을 하나**: Claude Code 라이프사이클에 훅으로 붙어, **개입 없이** 세션을 저장하고 Haiku 로 압축해 다음 세션 시작 시 컨텍스트에 되돌려 놓는다.

```
tool use → save-session.sh → extract(Python) → summarize(Haiku)
        → now.md ─(시간별 압축)→ today-YYYY-MM-DD.md ─(일별 통합)→ recent.md + archive.md
```

`SessionStart` 훅이 매 세션 자동 주입하는 것: `identity.md`(에이전트 정체성) · `remember.md`(**지난 세션 핸드오프**) · `now.md`(현재 버퍼) · `today-*.md` · `recent.md`(최근 7일) · `archive.md`.

**`/remember` 스킬**: 세션 끝에 호출하면 **20줄 이내 핸드오프 노트**를 `.remember/remember.md` 에 남긴다(형식: `## State` / `## Next` / `## Context`). 다음 세션 시작 시 **가장 먼저** 주입된다.

**설치**:
```
/plugin marketplace add Digital-Process-Tools/claude-marketplace
/plugin install remember@dpt-plugins
```
*(공식 마켓플레이스 `/plugin` → "remember" 로도 설치 가능. 단 공식 쪽은 배포가 늦는 것으로 알려져 있어 위 DPT 마켓플레이스를 권장한다 — 플러그인 README 의 주장이며, 이 머신엔 공식 경로로 0.8.3 이 들어와 있으므로 현재는 둘 다 최신일 수 있다.)*

**요구사항**: Python 3.9+ · `claude` CLI(Haiku 접근) · Bash 4+ · `jq`
**비용**: 세션 저장 1회 **< $0.01**(Haiku). 하루 종일 굴려 몇 센트 수준.
**저장 위치**: `<project>/.remember/` (기본) 또는 `~/.remember/<slug>/` (external 모드) → **`.gitignore` 필수**.

#### 어떻게 "빈 곳을 메우는가" — 이게 이 도구의 정확한 용처다

| 상황 | ①② 만 있을 때 | ④가 있을 때 |
|---|---|---|
| 세션이 컨텍스트 한계로 갑자기 끊김 | 회차 기록 없음 → **통째로 증발** | `now.md` 에 이미 압축돼 있음 |
| 마감 체크리스트를 깜빡함 | 다음 세션이 낡은 표기를 믿음 | 핸드오프가 실제 상태를 알려줌 |
| "이 접근은 시도했다 버렸다"는 사실 | 아무도 안 적는다 → **6개월 뒤 재시도** | 세션 로그에 남아 있음 |
| "왜 B 말고 A 로 했지?" | ADR 이 있으면 O, 없으면 X | 그날의 대화가 요약돼 있음 |

> ⚠️ **정본으로 인용하지 마라.** ④는 **Haiku 압축**이다 — 손실이 있고, 숫자·해시가 뭉개질 수 있다.
> **역할**: ④는 **"뭘 했더라"의 실마리**를 준다. 그 실마리로 ①②(정본)와 git log(1차 사료)를 확인해 사실을 확정한다.
> 반대로 ④에서 건진 것 중 **재사용 가치가 있는 것은 즉시 ①②로 승격**시킨다(gotcha 로, 회차 기록으로). ④는 흐르는 물이고 ①②는 그릇이다.

## 9. 📦 추천 스킬 — 신규 프로젝트에서 먼저 깔 것

> 이 키트는 **"무엇을 어디에 적는가"** 를 정의한다. 스킬은 그것을 **실제로 그렇게 적게 만드는 실행 장치**다.
> 셋업 시(§0 Step 6) 이 목록을 설치한다. **목록은 늘어난다** — 새 프로젝트에서 반복해서 아쉬웠던 스킬이 생기면 여기에 추가한다.

### `doc-writer` — 문서 산출물의 타입·네이밍·관점 고정

**왜 필요한가.** 이 키트는 `CLAUDE.md`(정본)와 `CLAUDE.local.md`(시간축)만 규정한다. 그런데 프로젝트가 굴러가면 **그 둘에 넣으면 안 되는 것들**(조사 결과, 설계 결정, 진행 보고서, 실행 가이드)이 반드시 쌓인다. 이걸 방치하면 `docs/` 는 이름 규칙 없는 파일 더미가 되고, 정본에 넣으면 §1 의 4층 분리가 무너진다. `doc-writer` 는 그 배출구를 **타입별로 규격화**한다.

**무엇을 하는가.**
- **3문서군 분류** — 협업 문서(PRD·STRATEGY·PLAN·RESEARCH·ANALYSIS·ADR) / 전달 문서(REPORT·DOCUMENTATION·GUIDE — 외부 전달 가능 수준으로 작성) / 개인 메모(NOTE)
- **아카이브 처리**(스킬 §9) — **아카이브는 타입이 아니라 상태다.** 수명이 끝난 문서는 원래 타입·파일명을 그대로 둔 채 `status: archived` 로 바꾸고 `docs/_archive/` 로 옮긴다. 이름을 바꾸면 기존 `related_docs` 링크가 전부 깨지고, 본문을 손보면 기록이 아니라 위조가 된다.
- **네이밍·프론트매터 강제** — 파일명 `{TYPE}-{주제}-{YYYY-MM-DD-HHMM}.md`, 프론트매터 필수 `type`·`audience`·`created`·`status`·`description` / 선택 `related_docs`·`updated`.
  **이 규격이 정본은 doc-writer 쪽이다.** 키트 템플릿의 `CLAUDE.md` §8 문서 규율(R1~R4)은 그 규격을 그대로 따르도록 맞춰져 있다 — 특히 `status` 는 **`draft`·`active`·`superseded`·`rejected`·`archived` 5종**으로 양쪽이 동일하다. 스킬을 업데이트해 규격이 바뀌면 **`CLAUDE.md` R3 을 스킬 쪽에 맞춰 고쳐라**(반대 방향이 아니다). 두 어휘가 갈리면 인덱스의 🟢/🟡 파생 표시가 곧 어긋난다.
- **고정 템플릿 없음** — 타입별 Persona 관점만 주고 문서 형태는 상황에 맞춘다.
- **오작동 억제** — "분석해줘"·"조사해봐" 처럼 **대화로 답하면 되는 요청엔 문서를 만들지 않는다.**

**설치 (Claude 가 §0 Step 6 에서 수행)**

```bash
# 원본: rules 저장소 (마스터 템플릿)
cp -r /Users/sspark/Work/rules/ClaudeCode/.claude/skills/doc-writer  ./.claude/skills/   # 프로젝트 전용
# 또는 모든 프로젝트에서 쓰려면
cp -r /Users/sspark/Work/rules/ClaudeCode/.claude/skills/doc-writer  ~/.claude/skills/   # 사용자 전역
# (원본 경로가 이 머신에 없으면 추측해서 만들지 말고 사용자에게 경로를 물어라 — §0 Step 6)
```

- 구성 파일 3개: `SKILL.md` · `references/writing-principles.md` · `references/personas.md` — **폴더째** 복사한다(references 를 빠뜨리면 문체·관점 규칙이 통째로 사라진다).
- 이미 `~/.claude/skills/doc-writer` 가 있으면 **다시 깔지 않는다** — 전역 설치가 프로젝트 복사본보다 유지보수가 쉽다.
- 설치 확인: 새 세션에서 `/` 목록에 뜨는지, 또는 "이 내용 문서로 정리해줘" 에 반응하는지(§7 스킬 테스트).
