# 세션 간 지식 관리 — 현황 분석과 확정 결정

## 1. 결론

**키트 규율은 채택된 곳에서 거의 다 작동한다. 실패하는 것은 규율이 아니라 사본 동기화와 발명의 역류다.**

키트를 실제로 적용한 두 프로젝트를 파고든 결과가 이 결론을 떠받친다.

| 규율 | agent-studio | agent-composer-core | 판정 |
|---|---|---|---|
| 세션 마감 기록 | 66차까지 · 격차 1일 | 8차까지 · 로컬이 커밋보다 최신 | ✅ |
| 아카이빙 | **7건** · 링크 전부 유효 | **4건** | ✅ |
| 문서 프론트매터 규격 | `docs/` 67건 **100%** | `_docs/` 6건 **100%** | ✅ |
| 전략·전술 이원화 | §6 번호 고정 · 로컬은 취소선 | 동일 | ✅ |
| 킷 사본 동기화 | ⚠️ 커밋 하나만큼 뒤처짐 | ✅ 동일 | ⚠️ |
| 발명의 킷 역류 | ❌ 6건 미반영 | ❌ | ❌ |

두 프로젝트 다 `CLAUDE.local.md` 가 **정확히 40KB에서 잘린다** — 키트가 정한 임계값 그대로다. 규율은 살아 있다.

따라서 손댈 곳은 세 군데다. **① 킷 사본이 갈라지는 것을 구조로 막고**(§4.2), **② 두 프로젝트가 발명한 6건을 킷이 받고**(§5), **③ 현실과 3~6배 어긋난 크기 상한을 고친다**(§4.3).

세션 마감·저장·인덱스에 대한 결정은 §6 에 확정해 둔다 — 훅도 커스텀 커맨드도 쓰지 않는다.

## 2. 조사 범위와 방법

키트를 실제로 채택한 프로젝트만 대상으로 삼았다. 판별은 `CLAUDE.local.md` 에 회차 섹션(`^## .*[0-9]+차`)과 마감 체크리스트가 있는지다.

| 프로젝트 | 회차 섹션 | 마감 체크리스트 | 조사 대상 |
|---|---|---|---|
| agent-studio | 6개 (66차까지) | 있음 | ✅ 주 대상 |
| agent-composer-core | 3개 (8차까지) | 있음 | ✅ 주 대상 |
| bmad2 | 26개 | 있음 | 참고 (미유지) |
| rules · axplatform | 0개 | 없음 | ➖ 대상 아님 |

측정은 파일 크기·줄 수·git 이력·프론트매터 필드 유무의 전수 집계로 했고, 결론을 떠받치는 값은 다른 축으로 한 번 더 셌다.

> ⚠️ **초안(v1·v2)의 실측 오류 셋을 여기 남긴다** — 같은 숫자를 보고 같은 오판에 다시 도달하지 않도록.
> - **"아카이빙은 한 번도 발동하지 않았다"** — bmad2 하나를 보고 일반화했다. 실제로는 studio 7건·core 4건으로 작동 중이다.
> - **"`_docs/` 를 지시하는 프로젝트 `CLAUDE.md` 가 0개"** — 검색 깊이를 2로 잡아 `dev2/*` 를 통째로 놓쳤다. 실제로는 3개다(core 20회·studio 6회·bmad2 2회 언급 — 전부 킷 채택 프로젝트).
> - **"발명의 역류 경로가 없다"** — 역류는 2026-07-31 커밋 `e87f2b6`("agent-studio 최신본 동기화")로 실제 일어났다. 없는 것은 역류가 아니라 **그 뒤의 순방향 전파**다.
> - **`rules` 의 22일 마감 격차** — 이 저장소는 회차 규율을 채택한 적이 없다(회차 섹션 0개, 17줄짜리 롤링 메모). 미이행이 아니라 대상 아님이다.

## 3. 킷의 진화 — 두 프로젝트를 거친 경로

키트는 설계된 것이 아니라 **agent-studio 에서 추출되고 core 에서 검증된** 것이다.

```
agent-studio (2026-07-02 착수 · 최초 적용지)
     │  6주 20회차의 실물에서 패턴 추출
     ▼
rules/bootstrap-kit  07-12 df57518  최초 등재
                     07-12 1503016  프로젝트 종속 찌꺼기 제거
                     07-15 79566c5  §10 루프 엔지니어링 · 기억 4층→3층
                     07-26 5736313  §11 오버레이 모드
     │
     ├──▶ agent-composer-core (07-14 착수 · 두 번째 적용지)
     │         │  루프 5파일 전부 채택 · 검증 루프를 실제로 돌림
     │         ▼
     ▼    07-31 e87f2b6  doc-writer 배선 + agent-studio 최신본 역류  ◀── 역류 1회
```

이 그림이 드리프트의 정체를 설명한다. **역류는 한 번 일어났고, 그 뒤 순방향 전파가 없었다.**

## 4. 실측 현황

### 4.1 작동하는 것

**마감과 아카이빙.** 두 프로젝트 다 `CLAUDE.local.md` 가 40KB에서 잘린다. agent-studio 는 66차까지 가면서 7번 아카이브했고 목록의 링크 7개가 전부 살아 있다(전수 확인). core 는 4번 했다. 키트가 "유일한 위험 구간"이라 부른 절차가 11회 무사고로 돌았다.

미작동은 bmad2 하나다 — 아카이브 절은 있으나 0건이고, 26회차 124KB 가 매 세션 전량 로딩된다. 다만 bmad2 는 마지막 커밋이 2026-04-29 로 활성 프로젝트가 아니다.

**문서 규율.** `_docs/` 를 지시한 3개 프로젝트에서만 `_docs/` 가 쓰이고, 지시하지 않은 20개에서는 전혀 쓰이지 않는다. 어렵기 때문이 아니라 **지시하지 않았기 때문**이다.

규격 준수율은 지시한 곳에서 완벽하다.

| 대상 | 문서 수 | 프론트매터 + `status` 정상 |
|---|---|---|
| agent-studio `docs/` | 67 | **67 (100%)** |
| agent-composer-core `_docs/` | 6 | **6 (100%)** |
| rules `docs/` (규율 없음) | 16 | 7 (44%) — `status` 누락 3 · 프론트매터 없음 6 |

**전략·전술 이원화.** 키트가 경고한 "다음 후보 양쪽 복사" 안티패턴을 두 프로젝트 다 피하고 있다. agent-studio `CLAUDE.md` §6 은 *"즉시 착수 목록(전술)은 `CLAUDE.local.md` · 전략 로드맵 정본은 여기 · 번호는 다른 문서가 인용하므로 바꾸지 않는다"* 를 명시하고, 실제로 `PLAN-CANVAS` 가 "후보 10-①", `REPORT-CANVAS` 가 "후보 3" 을 가리킨다. 번호 고정이 장식이 아니라 실사용 중이다.

### 4.2 작동하지 않는 것 — 킷 사본 드리프트

| 사본 | 위치 | git 추적 | 원본 대비 |
|---|---|---|---|
| agent-composer-core | `_docs/bootstrap-kit/` (킷 규정대로) | **미추적** | ✅ 5파일 전부 동일 |
| agent-studio | **루트 `bootstrap-kit/`** (위치 이탈) | **5파일 추적** | ⚠️ README 26줄 차 |
| bmad2 | 루트 `bootstrap-kit/` | 미추적 | ❌ README 353줄 차 · 2파일 결손 |

**agent-studio 의 26줄 차이는 정확히 커밋 `305b18e`(08-07) 하나다.** 그 커밋이 README 를 26줄 고쳤고(24 추가·2 삭제), 대표 문구 3개("루프에는 두 유형이 있다" · "미추적인 환경에서는 이 대응이 무효" · "루프 도중 새로 만든 운영 파일도")를 studio 사본에서 찾으면 전부 0건이다. core 사본에는 있다.

즉 잃고 있는 것은 **검증 루프 유형 구분 · 미추적 환경의 gotcha 삭제 금지 예외 · 워크트리 커밋 위생 보강** 셋이다. agent-studio 는 자기가 낳은 킷의 최신판을 못 받고 있다.

#### 대응 — 심링크와 그 한계

정본을 `rules/bootstrap-kit` 하나로 두고 프로젝트는 심링크로 참조하면 드리프트가 원천 차단된다. 킷은 **상시 로딩되는 데이터가 아니라** 셋업할 때와 규칙을 의심할 때만 여는 문서이므로, 심링크의 비용(원본이 있어야 한다)이 일상 작업에 걸리지 않는다.

다만 **추적 상태가 갈려서 프로젝트마다 답이 다르다.**

| 프로젝트 | 추적 | 심링크 전환 | 근거 |
|---|---|---|---|
| agent-composer-core · bmad2 | 미추적 | ✅ 즉시 가능 | 저장소 콘텐츠에 영향이 없다 |
| agent-studio | 5파일 추적 | ⚠️ 판단 필요 | 커밋 내용이 바뀌고, 다른 머신에서 클론하면 절대경로 링크가 깨진다 |

추적 사본에 쓸 수 있는 대안은 둘이다 — **사본을 지우고 `CLAUDE.md` 에 원본 경로만 남기거나**(킷을 읽을 일이 생기면 그때 원본을 연다), **README 프론트매터에 킷 버전(커밋 해시)을 박고** 세션 시작 시 원본과 대조하는 것이다. 전자는 저장소 자립성을 잃고 후자는 대조 절차가 사람 손에 남는다.

### 4.3 상한과 현실의 괴리

| | 키트 상한 | 공식 권장 | 실제 |
|---|---|---|---|
| agent-studio `CLAUDE.md` | 10~15KB | 200줄 | **84KB / 392줄** |
| agent-composer-core `CLAUDE.md` | 10~15KB | 200줄 | **52KB / 274줄** |

그런데 내용은 버릴 것이 없다. agent-studio 의 gotcha 는 **26개**이고 §5 만 68줄을 차지하는데, 이 저장소에서 가장 값비싼 자산이며 키트가 요구한 **재발 조건 형태**로 정확히 쓰여 있다. gotcha 17 은 *"트리거는 '매크로를 추가했나'가 아니라 '목적지를 가리키는 필드가 늘었나'"* 로, 세 번 재발한 끝에 조건을 바로잡은 기록이다.

**상한이 틀렸거나, 상한을 지킬 배출구가 부족하다.** agent-studio 는 인덱스를 빼내는 데는 성공했지만(§5 ③) gotcha 는 못 뺐다 — 뺄 자리가 키트에 없기 때문이다.

배출구는 `.claude/rules/` + `paths:` 프론트매터다(§6.4). 그리고 키트의 "10~15KB" 는 **"gotcha 를 뺀 나머지 10~15KB"** 로 고치는 것이 실측에 맞다.

## 5. 두 프로젝트가 발명했으나 킷에 없는 것

### ① `_docs/_linked/` — 저장소 간 심볼릭 링크 (core)

core 가 agent-studio 의 문서를 `_docs/_linked/agent-studio/` 에 심링크로 걸고, 인덱스에 성격을 명시했다 — *"원본은 agent-studio 소유 · 저쪽이 고치면 즉시 반영되고 **여기서 편집하면 원본이 바뀐다 — 읽기 전용으로 쓴다**"*.

**프로젝트를 가로지르는 연결 문제의 이미 돌아가는 해법이다.** 복사가 아니라 참조라 원본이 움직여도 낡지 않는다. §4.2 의 킷 사본 문제에 그대로 적용된다.

### ② 압축 사다리 — 독자별 3단 (core)

```
ANALYSIS-POC-GAP-LEDGER      갭 28건 전수 · 추적 정본        → 우리용
        │ 압축
REPORT-CORE-GAP-FINDINGS     248줄 · 5군 분류 · 재확인 명령   → 회의·전달용
        │ 압축
REPORT-CORE-GAP-SUMMARY      약 130줄 · 해시+문제+결정지점만  → 원저자에게 바로 건넴
```

같은 사실을 세 벌 쓴 것이 아니라 **독자가 감당할 밀도로 세 번 깎은** 것이고, 각 단계에 규율이 붙어 있다 — 압축본은 *"본문이 자립하도록 외부 문서를 참조하지 않는다"*(계보는 프론트매터에만), 최종본은 *"판단이 바뀌지 않는 방법론·자평·내부 감사 통계는 싣지 않는다"*.

키트도 doc-writer 도 이 개념이 없다. doc-writer 는 타입만 가르고 **같은 내용의 밀도 단계**는 다루지 않는다.

### ③ 중첩 `docs/CLAUDE.md` 인덱스 (agent-studio)

문서 인덱스를 루트에서 빼내 `agent-studio/docs/CLAUDE.md`(443줄 · 90,790바이트)에 두었다. 서브디렉토리의 `CLAUDE.md` 는 **그 폴더 파일을 읽을 때만 로딩**되므로 인덱스가 매 세션 비용을 물지 않는다. 루트 §7 에 남긴 근거가 정확하다 — *"여기에 표를 복제하지 않는다 — 이중 유지가 드리프트를 낳는다(과거 이 자리의 인덱스 표는 실제로 뒤처졌다)"*.

인덱스가 가리키는 문서를 전수 확인했는데 **깨진 링크 0건**이다. `Work` 하위를 전수 검색하면 중첩 `CLAUDE.md` 를 쓰는 프로젝트는 **agent-studio 하나뿐**이다.

⚠️ 이 파일의 `updated: 2026-07-24` 인데 실제 수정은 **07-31** 이다. 키트 R4 가 *"`created`↔`updated` 격차가 살아있다는 유일한 신호"* 라고 규정한 그 필드가 7일 뒤처졌다. 다른 문서의 상태를 판정하는 자리라 특히 곤란하다.

## 6. 확정된 결정

### 6.1 세션 마감 — `CLAUDE.md` 상태 표시 한 줄

**훅 기각.** `settings.json` 등록·프로젝트별 경로·워크스페이스 신뢰 승인을 요구하는 새 관리 축이라 "키트 내 파일과 git 만으로 동작한다"는 자립성 전제를 깬다. 그리고 §4.1 대로 강제할 대상이 없다. (검증까지 끝낸 스크립트는 §10 부록에 보존한다.)

**커스텀 커맨드 기각.** 키트와 항상 세트로 따라다녀야 한다. 키트가 `doc-writer` 조차 "하드 의존은 아니다"라고 못박은 것과 같은 이유다.

**현행 규칙의 결함은 강제력이 아니라 트리거였다.** 지금 규칙은 "세션 **종료 전** 수행한다"인데 **Claude 는 세션이 끝나는 시점을 관측할 수 없다.** 무시당한 것이 아니라 발동 조건이 원리적으로 감지 불가능했다. 상태 표시는 트리거를 "커밋했다"로 옮긴다 — Claude 가 직접 실행한 행위라 조회 없이 확실히 안다.

**형식은 질문이 아니라 상태다.** "회차 기록을 할까요?"는 매번 답을 요구하므로 커밋을 3번 하면 3번 묻게 된다. 상태 표시는 답을 요구하지 않아 반복돼도 갱신이 된다.

### 6.2 문서 저장 — 인박스

세션 중 "남겨야 한다"는 순간에 정식 문서를 만드는 것은 비싸고 승인 게이트도 걸린다. 그 순간엔 `_docs/_inbox.md` 에 한 줄만 붙이고 마감 때 승격 여부를 판단한다. 인박스는 문서가 아니라 대기열이므로 프론트매터를 요구하지 않는다.

### 6.3 `docs/` 승격 — 마감에서 묻지 않는다

승격 판단이 필요해지는 시점은 세션 마감이 아니라 **과제나 단계가 끝나고 "이걸 밖에 낼까"가 실제로 생길 때**이고, 그 주기는 세션 주기와 다르다. 마감마다 물으면 대부분 "아니오"가 나오고 질문 자체가 소음이 된다.

대신 **인덱스가 표시만 한다.** 새 메타데이터도 필요 없다.

```
판정: type ∈ {report, guide, documentation}  AND  status == active   →  📤

Claude 는 판단도 질문도 하지 않는다
                    │
                    ▼
        인덱스에 📤 가 쌓인다  ──▶  사람이 외부 전달할 일이 생겼을 때
                                    인덱스를 열어 고르고 `git mv` 한다
```

`rules/docs` 에 적용해 승격 후보 3건(GUIDE 3종)을 얻었고, 별도 스크립트로 독립 재검산해 같은 값을 확인했다.

> ⚠️ core 에는 이 개념이 없다 — *"`docs/` 는 상류의 정식 산출물이다. 승격하려면 폴더를 옮기는 게 아니라 상류에 PR 을 낸다."* 저장소가 남의 코드를 포크한 경우 2단 모델의 의미가 달라진다는 실례다.

### 6.4 gotcha 는 `CLAUDE.md` 유지

두 지식의 발동 방식이 반대다. **gotcha 는 찾아가는 지식이 아니라 발동해야 하는 지식**이라, 함정에 빠지기 직전에 경고하려면 이미 컨텍스트 안에 있어야 한다. 파일로 빼면 "그 파일을 열어야겠다"는 판단이 선행돼야 하는데, 함정은 **빠질 줄 몰라서 빠지는 것**이라 그 판단이 서지 않는다. 회차 기록은 정반대로 질문이 먼저 생기고 그 다음에 찾아간다.

키트가 이미 이 구분을 갖고 있다 — §4 4항의 *"회차 기록에만 적는 것은 등재가 아니다"* 가 정확히 이 이유이고 실제 사고를 겪고 생긴 규칙이다.

**규모가 커질 때의 배출구**는 `.claude/rules/` + `paths:` 프론트매터다. 판별은 **함정의 재발 조건이 특정 경로에 묶이는가**다.

| 함정의 성격 | 자리 | 예 |
|---|---|---|
| 경로에 안 묶임 (환경·빌드·전역 규약) | `CLAUDE.md` §5 유지 | venv · 패키지 매니저 · 인증 |
| 경로에 묶임 (이 모듈 만질 때만) | `.claude/rules/gotcha-{영역}.md` + `paths:` | 특정 컴파일러 · 스키마 |

> ⚠️ `paths:` 스코프 룰은 **compact 이후 자동 재주입되지 않는다**(루트 `CLAUDE.md` 는 재주입된다). 긴 세션에서 compact 가 걸리면 조용히 사라지므로, **한 번 밟으면 치명적인 함정은 200줄을 넘기더라도 루트에 둔다.**

## 7. 인덱스 생성기

`CLAUDE.md` §7 의 문서 인덱스를 손으로 유지하면 반드시 낡는다 — agent-studio 가 *"과거 이 자리의 인덱스 표는 실제로 뒤처졌다"* 로 증언한다. doc-writer 자신의 원칙("파생값을 저장하지 않는다")과도 충돌한다.

`rules/docs` 에 실행한 결과 10건 등재·6건 누락으로 총 16건이 맞았고, 부수 효과로 **규격 이탈 9건을 자동 검출**했다. 인덱스 생성기가 곧 린터 역할을 한다.

```python
#!/usr/bin/env python3
"""문서 인덱스를 프론트매터에서 생성한다. 손으로 유지하는 인덱스는 반드시 낡으므로 파생값을 저장하지 않는다.

사용: python3 docs-index.py <문서폴더> [출력파일]
"""
import re, sys, pathlib, datetime

MARK = {"active": "🟢", "draft": "✏️", "superseded": "🟡", "rejected": "🟡", "archived": "📦"}
# 전달 문서군 — 외부에 그대로 내보낼 수 있는 타입. 이것이 active 면 docs/ 승격 후보다.
DELIVERABLE = {"report", "guide", "documentation"}


def front(p: pathlib.Path) -> dict:
    t = p.read_text(encoding="utf-8", errors="replace")
    m = re.match(r"^---\n(.*?)\n---\n", t, re.S)
    if not m:
        return {}
    out, key = {}, None
    for line in m.group(1).splitlines():
        if re.match(r"^\s*-\s", line) or line.startswith(("  ", "\t")):
            continue  # 블록 리스트 항목은 인덱스에 안 쓴다
        if ":" in line:
            key, _, val = line.partition(":")
            out[key.strip()] = val.strip().strip('"').strip("'")
    return out


def main() -> int:
    root = pathlib.Path(sys.argv[1] if len(sys.argv) > 1 else "_docs")
    if not root.is_dir():
        print(f"폴더 없음: {root}", file=sys.stderr)
        return 1

    rows, missing = [], []
    for p in sorted(root.rglob("*.md")):
        if p.name in ("INDEX.md", "README.md"):
            continue
        f = front(p)
        if not f:
            missing.append(p)
            continue
        desc = f.get("description", "")
        first = re.split(r"(?<=[.다])\s", desc, maxsplit=1)[0] if desc else "(description 없음)"
        status, typ = f.get("status", "?"), f.get("type", "?").lower()
        rows.append((
            status,
            p.relative_to(root).as_posix(),
            typ,
            f.get("updated") or f.get("created", "")[:10],
            first,
            "📤" if (typ in DELIVERABLE and status == "active") else "",
        ))

    # 살아있는 것 먼저, 그 안에서 최신순
    order = {"active": 0, "draft": 1, "superseded": 2, "rejected": 2, "archived": 3}
    rows.sort(key=lambda r: (order.get(r[0], 9), r[3]), reverse=False)
    rows.sort(key=lambda r: order.get(r[0], 9))

    promo = sum(1 for r in rows if r[5])
    out = [f"# 문서 인덱스 — `{root.as_posix()}/`", "",
           f"> 이 파일은 각 문서의 프론트매터에서 생성된다. 직접 고치지 마라 — 문서 쪽을 고치고 다시 생성한다.",
           f"> 생성: {datetime.date.today()} · 문서 {len(rows)}건 · 📤 승격 후보 {promo}건", "",
           f"> 📤 = 전달 문서군({'·'.join(sorted(DELIVERABLE))})이면서 active — **외부로 낼 일이 생겼을 때** 골라서 `git mv` 한다.",
           "> 표시일 뿐 요청이 아니다. 승격 시점은 사람이 정한다.", "",
           "| | 📤 | 문서 | 타입 | 갱신 | 결론 |", "|---|---|---|---|---|---|"]
    for st, rel, ty, dt, first, pm in rows:
        out.append(f"| {MARK.get(st, '❔')} | {pm} | [`{rel}`]({rel}) | {ty} | {dt} | {first} |")

    if missing:
        out += ["", "## ⚠️ 프론트매터 없음 — 인덱스에 못 올림", ""]
        out += [f"- `{p.relative_to(root).as_posix()}`" for p in missing]

    text = "\n".join(out) + "\n"
    dest = pathlib.Path(sys.argv[2]) if len(sys.argv) > 2 else root / "INDEX.md"
    dest.write_text(text, encoding="utf-8")
    print(f"{dest} — {len(rows)}건 등재, 프론트매터 누락 {len(missing)}건")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

```markdown
1. **회차 기록** — git log 가 갖지 못하는 것만 쓴다: 발단(사용자 요청 한 줄) · 판단 근거 ·
   잔여 미커밋(무엇이 **왜**) · 다음 후보. 무엇을 바꿨는지는 커밋 해시로 가리킨다.

3. **함정 등재** — 재발 조건이 있는 함정은 이 파일 §5 로. **회차 기록에만 적는 것은 등재가 아니다.**
4. **인덱스 재생성** — `python3 scripts/docs-index.py _docs`. 손으로 고치지 않는다.

### 문서 저장

- **작성은 `doc-writer` 스킬로, 위치는 `_docs/` 하나다.** 타입이 위치를 가르지 않는다.
- **인박스 — 문서로 만들기 전 단계.** 세션 중 "남겨야 한다"고 판단하면 정식 문서를 만들지 말고
  `_docs/_inbox.md` 에 `- {YYYY-MM-DD} {한 줄} → 후보 타입: ADR|RESEARCH|PLAN` 한 줄만 붙인다.
  프론트매터를 요구하지 않는다 — 이건 문서가 아니라 대기열이다.
  마감 때 인박스를 훑어 **승격할 것만** 사용자 승인을 받아 정식 문서로 쓰고, 그 줄을 지운다.
- **`docs/` 승격은 묻지 않는다.** 인덱스가 📤 로 표시하고, 외부 전달할 일이 생겼을 때 사람이 고른다.
  Claude 는 승격을 제안하지도 실행하지도 않는다.
```

- **킷 사본 동기화 방식** — core·bmad2 는 미추적이라 심링크가 즉시 가능하나, agent-studio 는 5파일이 git 추적 중이라 저장소 자립성과 맞바꿔야 한다(§4.2).
- **압축 사다리의 자리** — 킷인가 doc-writer 인가. "문서를 어떻게 쓰는가는 스킬 소관"이라는 킷의 분업 규칙에 따르면 doc-writer 쪽인데, 그러면 킷을 안 쓰는 프로젝트에도 적용된다.
- **회차 파일 분리** — 아카이빙이 실제로 작동 중이므로(§4.1) 근거가 "실패를 없앤다"에서 "절차를 싸게 만든다"로 내려앉았다. 여전히 유효하지만 우선순위가 아니다. core 가 `progress-audit.md` 로 부분 실행 중이라 그 경험을 먼저 본다.
- **상태 표시의 실효** — 이 장치는 "잊어버림"은 막지만 "미루기"는 못 막는다. 한동안 돌려보고 누락이 반복되면 §10 부록을 되살린다.

## 10. [부록] 기각한 안 — Stop 훅 마감 게이트

§6.1 대로 기각했으나 검증까지 끝난 안이라 보존한다. **되살릴 조건**: 키트 규율을 채택한 프로젝트에서 상태 표시(§8)를 걸고도 마감이 반복적으로 누락될 때. 그때는 "잊어버림"이 아니라 "미루기"이므로 알림으로는 부족하다.

`SessionEnd` 가 아니라 `Stop` 이어야 한다 — 공식 문서상 `SessionEnd` 는 차단 능력이 없어 로깅·정리 같은 부수효과만 가능하고, `Stop` 만 `decision: "block"` + `reason` 으로 Claude 를 멈추지 못하게 하고 이유를 되돌려준다.

5가지 경계에서 실행 검증했다 — 마감 밀린 저장소에서 발동(536시간 격차·미커밋 7건 보고), `stop_hook_active` 시 침묵, `CLAUDE.local.md` 없으면 침묵, git 저장소 아니면 침묵, 마감이 최신이면 침묵.

```bash
#!/usr/bin/env bash
# 세션 마감 게이트 — Stop 훅용.
# 커밋이 생겼는데 CLAUDE.local.md 가 그 커밋보다 오래됐으면 Claude 를 멈추지 못하게 하고 마감을 시킨다.
# 조건이 아니면 조용히 통과한다(exit 0). 매 턴 발동하는 훅이므로 침묵이 기본값이다.

set -uo pipefail
IN=$(cat)

# 이미 이 훅 때문에 재개된 턴이면 즉시 빠진다 (무한 루프 방지)
if [ "$(printf '%s' "$IN" | jq -r '.stop_hook_active // false')" = "true" ]; then exit 0; fi

CWD=$(printf '%s' "$IN" | jq -r '.cwd // ""')
[ -n "$CWD" ] && cd "$CWD" 2>/dev/null || exit 0

# git 저장소가 아니면 대상 아님
git rev-parse --git-dir >/dev/null 2>&1 || exit 0

LOCAL_FILE="CLAUDE.local.md"
[ -f "$LOCAL_FILE" ] || exit 0          # 키트를 안 쓰는 저장소면 대상 아님

# 마지막 커밋 시각 (커밋이 하나도 없으면 대상 아님)
LAST_COMMIT=$(git log -1 --format=%ct 2>/dev/null) || exit 0
[ -n "$LAST_COMMIT" ] || exit 0

# CLAUDE.local.md 최종 수정 시각 (BSD/GNU stat 양쪽)
LOCAL_MTIME=$(stat -f %m "$LOCAL_FILE" 2>/dev/null || stat -c %Y "$LOCAL_FILE" 2>/dev/null) || exit 0

# 커밋이 마감 기록보다 나중이 아니면 통과
[ "$LAST_COMMIT" -gt "$LOCAL_MTIME" ] || exit 0

GAP_H=$(( (LAST_COMMIT - LOCAL_MTIME) / 3600 ))
UNCOMMITTED=$(git status --porcelain | wc -l | tr -d ' ')

jq -n --arg h "$GAP_H" --arg u "$UNCOMMITTED" '{
  decision: "block",
  reason: ("세션 마감이 밀렸다 — 마지막 커밋이 CLAUDE.local.md 보다 \($h)시간 앞서 있고, 미커밋 변경이 \($u)건이다.\n지금 마감 4항을 수행하라: ①회차 기록(커밋 해시 포함) ②수치 정본은 CLAUDE.md ③CLAUDE.md 상태줄·인덱스 동기화 ④재발 조건이 있는 함정은 CLAUDE.md gotcha 에 등재.\n초안은 `git log --oneline` 과 이번 세션 변경에서 뽑고, 사용자에게 확인받은 뒤 쓴다. 마감이 불필요한 세션이면 그 이유를 한 줄로 답하고 넘어가라.")
}'
exit 0
```
